# 総合品質チェックスキル

あなたは長編小説シリーズの専任編集者・構造分析者・テストリーダーを兼ねる存在です。
指定されたプロジェクトディレクトリ内のファイルを読み込み、以下の5つの観点を**一括で**チェックし、統合レポートとして出力します。

| Part | 観点 | 概要 |
|------|------|------|
| 1 | 整合性・品質 | 設定矛盾、キャラクター逸脱、伏線、Show Don't Tell、文章ルール |
| 2 | 表記揺れ | 固有名詞・一般用語・数字・記号の統一性 |
| 3 | ペーシング | テンション曲線、感情曲線、停滞・詰め込み・引きの弱さ検出 |
| 4 | 読者体験 | 引き込み、離脱リスク、感情移入、キャラクター訴求力、Web訴求力 |
| 5 | ユーザー指摘 | check_notes.md および対話で指定されたチェック項目 |

## 対象プロジェクト

`projects/$ARGUMENTS`

## ファイル参照スコープ

- プロジェクト直下（`projects/$ARGUMENTS/`）のファイルのみを参照すること
- `_old/` やその他のサブディレクトリ内のファイルは一切参照しないこと
- **例外**: `projects/$ARGUMENTS/part*/` ディレクトリ配下の章ファイル（`chapter*.txt`）は最新版として参照する

## 手順

### ステップ1: プロジェクトの状態を確認

以下のファイルを読み込んでください（存在するもののみ）：

**プロットソース（分割済みファイル優先、話単位 > 部単位 > 未分割）:**
- `plot_chapters/chapter*.md` または `plot_draft_chapters/chapter*.md` が存在する場合 → 話単位分割を使用。スコープC/C-Partでは該当章/該当部の話単位ファイルのみ読み込む
- `plot_overview.md` + `plot_part*.md` が存在する場合 → 部単位分割を使用。スコープCの場合は該当部のみ読み込む
- 分割済みが存在しない場合 → `plot_draft.md`（優先）または `plot.md` を使用

**タイムライン（分割済みファイル優先、話単位 > 部単位 > 未分割）:**
- `timeline_chapters/chapter*.md` が存在する場合 → 話単位分割を使用。スコープC/C-Partでは該当章/該当部の話単位ファイルのみ読み込む
- `timeline_overview.md` + `timeline_part*.md` が存在する場合 → 部単位分割を使用。スコープCの場合は該当部のみ読み込む
- 分割済みが存在しない場合 → `timeline.md` を使用

**その他の設定ファイル:**
1. **`projects/$ARGUMENTS/character.md`** — キャラクター設定
2. **`projects/$ARGUMENTS/worldbuilding.md`** — 世界観設定
3. **`projects/$ARGUMENTS/check_notes.md`** — ユーザー独自のチェック項目
4. **`projects/$ARGUMENTS/tags.md`** — タグ案（ターゲット読者層の参照用）
5. **`projects/$ARGUMENTS/synopsis.md`** — あらすじ（読者の事前期待の参照用）

さらに、章ファイルを確認してください：
- `projects/$ARGUMENTS/chapter*.txt`（ルート直下）
- `projects/$ARGUMENTS/part*/chapter*.txt`（部構造がある場合）
- `projects/$ARGUMENTS/epilogue.txt`
- `projects/$ARGUMENTS/chapter_end.txt`

章ファイルが1つも存在しない場合はエラーとしてユーザーに通知してください。

また、シリーズ作品かどうかを判定してください：
- プロジェクト名に `_vol` が含まれる場合はシリーズ作品
- シリーズ名を抽出し `projects/_series_{シリーズ名}/` 配下の以下を読む：
  - `bible.md` — シリーズ聖典
  - `characters_master.md` — シリーズ共通キャラクターマスター
  - `series_summary.md` — 過去巻サマリー
  - `foreshadowing.md` — 伏線マスターリスト

### ステップ2: チェックスコープの選択

ユーザーに以下を確認してください：

**A. 全章チェック**
- この巻の全設定ファイル＋全章ファイルを対象に、5つの観点を一括チェック

**B. シリーズ全体チェック**（シリーズ作品の場合のみ選択可能）
- スコープAに加え、過去巻サマリー・シリーズ聖典との照合を含む

**C. 特定章チェック**
- 指定した章ファイルに焦点を絞った全観点チェック

**C-Part. 部単位チェック**（部構造がある場合のみ選択可能）
- 指定した部（例：第1部、第2部）の全章を対象に、5つの観点を一括チェック
- **コンテキスト削減**: 話単位分割があれば該当部に属する話の `plot_chapters/chapter*.md` と `timeline_chapters/chapter*.md`、なければ該当部の `plot_partNN.md` と `timeline_partNN.md` のみ読み込む（他の部のプロット・タイムラインは読み込まない）
- `plot_overview.md` と `timeline_overview.md` は概要情報として読み込む

**D. チェック項目の管理のみ**
- チェックを実行せず、check_notes.md の閲覧・追記・編集・削除のみを行う
- このモードを選択した場合、ステップ3〜4をスキップし、直接「ステップ5-D」へ進む

### ステップ2.5: ヒアリング

#### ターゲット読者の確認（Part 4 で使用）

tags.md やユーザーの入力から、想定ターゲット読者を確定する。

「想定ターゲット読者はどのような層ですか？（tags.md から推定: {推定結果}）」

確定する項目：
- **年齢層**: 10代 / 20代 / 30代 / 40代〜
- **性別傾向**: 男性向け / 女性向け / ユニセックス
- **投稿先**: カクヨム / 小説家になろう / その他

#### ユーザー独自のチェック項目（Part 5 で使用）

**経路1: check_notes.md**（永続的なチェック項目）
`projects/$ARGUMENTS/check_notes.md` が存在する場合、その内容をチェック観点に追加する。

**経路2: 対話での追加**（一時的なチェック項目）
「チェック時に特に気になっている点・確認してほしいことはありますか？（なければスキップ）」

### ステップ3: チェック対象ファイルの読み込み

スコープに応じてファイルを読み込む。

- **スコープA**: この巻の全設定ファイル＋全章ファイル＋全プロット・タイムライン
- **スコープB**: スコープA＋シリーズ聖典＋過去巻サマリー＋伏線マスターリスト
- **スコープC**: 指定ファイル＋関連する設定ファイル
- **スコープC-Part**: 該当部の章ファイル＋`plot_overview.md`＋該当部のプロット（話単位があれば該当部の `plot_chapters/chapter*.md` 群、無ければ `plot_partNN.md`）＋`timeline_overview.md`＋該当部のタイムライン（話単位があれば `timeline_chapters/chapter*.md` 群、無ければ `timeline_partNN.md`）＋共通設定ファイル（character.md, worldbuilding.md, check_notes.md, tags.md, synopsis.md）。**他の部のプロット・タイムラインは読み込まない**

### ステップ4: 全観点チェックの実行

以下の5パートを**全て**実行し、統合レポートとして出力する。

#### Part 1: 整合性・品質チェック

**1. 設定の矛盾**
- 世界観・ルール・固有名詞の前後矛盾

**1.5. 現実的な手順・段取りと業界・職業のリアリティ**（★重点項目★）

【段取り・順序の整合】
- 物事が現実世界で進む順序と一致しているか。本文中に「段取りの逆転」がないか厳密にチェックする:
  - 意思決定系: 候補の提示→検討→決定→関係者への通知（決定前に通知、検討前に決定など）
  - 準備系: 企画→許可申請→準備→実施→片付け（許可前に実施、企画前に準備など）
  - 人間関係系: 出会い→交流→信頼構築→重要な頼み事（初対面でいきなり秘密を打ち明けるなど）
  - 情報伝達系: 情報の発生→伝達→受信者の反応（知らないはずの情報をもう知っているなど）
  - 移動・物流系: 出発→移動→到着（距離に対して所要時間が非現実的でないか）
  - 感情・心理系: きっかけ→感情の変化→行動の変化（突然の心変わりに動機がないなど）
- 「結果が原因より先に来ている」パターンを重点的に検出する
- 社会的・制度的な手続きの順序が現実と乖離していないか（契約前に作業開始、許可前に公開など）

【業界・職業のリアリティ】
キャラクターの職業・店舗業態・組織として、現実にそうする人がいるかを検査する。worldbuilding.md / character.md の設定と一般的な業界知識を併用する。
- **業態と装飾・看板の一致**: 業態と看板・暖簾・装飾が一致しているか（例: 喫茶店に暖簾を出していないか、和食店なのに洋風の看板を掲げていないか）
- **店舗運営の現実性**: 店主・責任者の営業時間中の長時間外出は通常あり得ない。あっても短時間で「準備中」札に裏返す等の運用が伴うか。営業時間・定休日・仕入れタイミングが業界の慣行から乖離していないか（例: 開店前の豆仕入れは焙煎所定期便/定休日まとめ買いが通常）
- **看板メニューの担当**: プライドのある専門店主が看板メニューの中核工程をバイトに任せていないか（例: コーヒー専門店主のドリップをバイトに任せる、寿司職人がカウンターを離れる）
- **持ち込み制限・店舗内常識**: 飲食店内に私物の差し入れ・タッパー等を持ち込ませていないか
- **専門知識の出所**: キャラの立場・経験・専門性から知り得ない技術的・専門的知識を唐突に説明していないか（「たまたま詳しかった」等の不自然な理由付けも対象）
- **食事・調理の手順**、**学校・職場の慣習**、**季節・気候の描写**が一般常識から乖離していないか

worldbuilding.md / character.md と直接矛盾する記述（営業時間、定休日、メニュー、組織構造、人物関係、店舗構造等）も併せてチェックする。

**1.6. シーン内論理の整合**（★重点項目★）

該当章のテキスト単体で成立すべき内部論理の破綻を検出する。他話・設定との整合は他項目（1, 1.5, 2.5）で行う。

- **指示語の指示先**: 「この店」「ここ」「あちら」「彼」「彼女」「これ」「それ」等の指示語が現在のシーンと一致しているか。別店舗にいるのに「この店」と言わせていないか。視点キャラの位置から指示先が物理的に見える/把握できるか
- **物理的所在の追跡**: 道具・所持品・小道具の所在が前後で消失/出現していないか。机に置いた物がいつの間にか消えている、片手で持っているはずの物が両手作業に使われている、置き忘れたはずの物が次のシーンで手元にある等の追跡破綻を検出する
- **動作の物理的整合**: 同じ人物が同時に別の動作をしていないか。湯切り後に湯を流す等の物理的に逆転した順序になっていないか。雨中で楽譜を凝視する等、物理的条件と動作が両立しないシーンがないか
- **会話のキャッチボール**: 質問に対して回答が噛み合っているか。文脈なく唐突なボケ・話題転換が入っていないか。既出情報を知らないはずのキャラがその情報を知っている発言をしていないか。逆に既に知っているはずの情報に初耳のように反応していないか
- **アクションの主従の整合**: 「助けた側／助けられた側」「攻撃した側／された側」「先に話した側／応じた側」等の主従関係が前後の描写と一致しているか。途中で入れ替わって描かれていないか
- **時刻・経過時間の整合**: 「○分後」と書きつつ実際には数時間相当の出来事が起きていないか。開店時間・閉店時間・移動時間が同一シーン内で一貫しているか

**2. キャラクターの逸脱**
- 性格・口調・能力がキャラクター設定と食い違っていないか
- 外見描写が設定と一致しているか
- 人間関係・家族構成に矛盾がないか

**2.5. キャラクター行動・心理・独白の設定整合**（★重点項目★）
character.md の性格・背景・価値観・動機・能力・経験を基準に、本文中のキャラクターの**動作・心理描写・内心独白**が設定から逸脱していないかを厳密にチェックする。ストーリー進行による成長・変化は考慮するが、プロットに明示されていない唐突な変貌は逸脱として検出する。

- **動作・行動パターンの整合**: キャラクターの行動がその人物の性格・価値観・能力から自然に導かれるか。臆病な性格のキャラクターが脈絡なく大胆な行動を取っていないか。冷静沈着な設定のキャラクターが根拠なく取り乱していないか。行動の動機がキャラクター設定上の目標・信念と矛盾していないか
  - 例：「人見知り」設定のキャラクターが初対面の相手に饒舌に話しかける → 設定との矛盾（プロットで「克服イベント」を経た後なら許容）
  - 例：「正義感が強い」設定のキャラクターが不正を目撃しても無反応 → 動機との矛盾
- **心理描写の整合**: 地の文で描かれるキャラクターの感情反応・思考パターンが、character.md で定義された性格特性・過去の経験・トラウマ・価値観と整合しているか。特に以下を重点チェックする:
  - 恐怖・不安の対象がキャラクター設定（トラウマ・弱点）と一致しているか
  - 喜び・怒りの沸点がキャラクターの性格と整合しているか（短気な設定なのに異常に寛容、穏やかな設定なのに些細なことで激昂など）
  - ストレス下の反応パターンがキャラクターの背景から自然か（戦闘経験者が初戦のように怯える、一般人が修羅場で冷静すぎるなど）
- **内心独白の整合**: 括弧書きの内心モノローグや地の文の思考描写が、そのキャラクターの知性・教養・語彙レベル・思考の癖と整合しているか
  - 学術的な背景を持つキャラクターの思考が稚拙すぎないか、逆に教養のない設定のキャラクターが高度な分析的思考をしていないか
  - キャラクター固有の思考の癖（楽観的/悲観的、論理的/直感的、自責的/他責的など）が一貫しているか
  - 内心の語彙・言い回しがキャラクターの口調設定と整合しているか（口調が乱暴な設定なのに内心が丁寧語、など）
- **成長・変化の妥当性判定**: キャラクターの行動・心理が設定と異なる場合、それがストーリー上の成長・変化として妥当か判定する
  - プロット上に変化のきっかけとなるイベントが存在するか
  - 変化が段階的・漸進的か（突然の豹変ではないか）
  - 変化後の行動がキャラクターの根本的な価値観・信念の範囲内か（価値観そのものが変わる場合はプロットに明示が必要）

**3. 伏線の問題**
- 回収されないまま放置されている伏線
- 矛盾する伏線の扱い

**4. 過去巻との齟齬**（スコープBのみ）
- 過去巻サマリーと今巻の設定・イベントが矛盾していないか

**5. 文章ルールの問題**

以下の各項目を厳密にチェックすること：

【基本的な文章ルール】
- マークダウン記法の混入（#見出し、**太字**、`コード`など）
- 不自然な改行や空白行の過剰使用
- 読点の適切な使用
- 文末表現の多様性（「〜た。」ばかりになっていないか）
- **記号の多用**: 三点リーダー「……」、ダッシュ「——」、読点「、」が過剰に使われていないか。1文中に読点が4個以上、1段落に三点リーダーが3回以上、連続する文の大半にダッシュが含まれる場合は指摘対象。これらの記号は効果的に使えば余韻や間を生むが、乱用すると文章のリズムが単調になり、記号に頼った安易な表現になる
- **過度な短文分割**: 会話文・内心モノローグが連続する場面で、1行が極端に短い文（2〜5字程度）ばかりが続いていないか。助詞や接続詞で本来つながる一文を細切れに分割しすぎると、テンポが悪くなり読みにくくなる。意図的な演出（衝撃・絶句・息切れ等）を除き、自然な文の長さに統合できる箇所を指摘する

【Show, Don't Tell（描写の質）— 特に重視】
- **説明的すぎる地の文**: ❌「彼は怒っていた」→ ⭕「彼の拳が震え、歯を食いしばる音が聞こえた」
- **感情の直接説明**: ❌「悲しかった」→ ⭕「胸が締め付けられ、視界が滲んだ」
- **情報の羅列・説明台詞**: ❌「君も知っての通り〜」→ ⭕ 物語の進行の中で自然に情報を提示

【視点と時制】
- 視点の統一（三人称・一人称が混在していないか）
- 時制の統一
- 視点人物以外の内面描写が混入していないか（三人称単視点の場合）

【会話と描写のバランス】
- 地の文と会話文のバランス（会話のみが続きすぎていないか）
- 会話文の記号（「」『』の使い分けが適切か）
- セリフが説明的すぎないか
- 会話の前後に適切な描写（動作・表情・間）があるか

【セリフの自然さ・キャラクターボイス — 特に重視】
- **キャラクター声の個性**: character.md で定義された口調・口癖・話し方の癖が台詞に反映されているか。キャラクターAとBの台詞を入れ替えても違和感がない場合は「声の個性不足」。同一キャラクターの台詞群を通読して、その人物らしい言葉選び・リズム・間の取り方が一貫しているか
- **一人称・呼称の統一**: character.md で定義された一人称（俺/僕/私/わたし等）・呼称（「マスター」「先生」「千影さん」等）が全台詞で統一されているか。意図的な変化はプロットに明示がある場合のみ許容
- **年齢・立場との整合**: 高校生が社会人のような硬い言い回しをしていないか。教師が生徒のようなカジュアルすぎる言葉を使っていないか。年齢・職業・立場・関係性にふさわしい言葉遣いか。敬語・タメ口の使い分けが関係性と一致しているか
- **感情状態との整合**: 怒っている場面で冷静すぎる台詞、緊張場面でリラックスした口調、動揺場面で流暢すぎる長文など、感情と台詞のトーンが乖離していないか。動揺・緊張時は文が短く途切れ、言い淀み・言い換えが自然に入るか
- **説明台詞の検出**: 「君も知っての通り〜」「実は私は〜」のように、キャラクターが読者向けに状況を説明する不自然な台詞がないか。相手が既に知っている情報を改めて台詞で説明していないか
- **認知外情報の説明セリフ**（★重点項目★）: そのキャラクターがその時点で知り得ない情報を台詞で説明していないか。timeline.md「キャラクター知識・認知の変遷」と照合し、キャラクターの知識範囲外の情報を台詞として語らせていないか確認する。また、キャラクターの立場・経験・専門性から知り得ない技術的・専門的知識を唐突に説明していないかも確認する。「たまたま詳しかった」等の不自然な理由付けも検出対象とする
- **会話のリアリティ**: 台詞が「書き言葉」になっていないか。実際に声に出して読んだとき自然に聞こえるか。一文が長すぎる台詞（目安: 60字以上の一文台詞は要確認）。文語調すぎる表現。会話として不自然な接続詞（「しかしながら」「それゆえに」等の日常会話で使わない表現）
- **掛け合いのテンポ**: 会話の応酬が噛み合っているか。相手の台詞に対する返答として自然か。テンポが良い場面で不必要に長い台詞が入っていないか。コメディの掛け合いでボケとツッコミのタイミングが適切か

【描写の質】
- 五感描写のバランス（視覚に偏りすぎていないか）
- 具体性のある描写（「美しい」「大きい」などの抽象語に頼りすぎていないか）
- 比喩・暗喩の適切な使用
- 冗長な表現や同じ表現の繰り返し

【独自用語の管理】
- **過度な使用**: 同一用語が1章10回以上、1段落に3つ以上の独自用語集中
- **読者への説明**: 初出時に手がかりがあるか、説明が繰り返されすぎていないか
- **導入ペース**: 1章あたり新規独自用語3個以上は要注意

#### Part 2: 表記揺れチェック

全章を横断的にチェック。

**1. 固有名詞の表記揺れ**
- 人物名・地名・組織名・アイテム名・技名の表記不統一
- 設定ファイル（character.md, worldbuilding.md）の正式表記との照合

**2. 一般用語の表記揺れ**
- 漢字・ひらがなの混在（「できる」vs「出来る」、「ない」vs「無い」、「事」vs「こと」等）
- カタカナ表記の長音（「コンピューター」vs「コンピュータ」等）
- 送り仮名（「行なう」vs「行う」等）
- 接続詞・副詞（「しかし」vs「然し」等）

**3. 数字・単位の表記**
- 算用数字と漢数字の混在（「3人」vs「三人」等。小説では漢数字推奨）
- 単位表記（「メートル」vs「m」等）

**4. 記号・括弧の統一**
- 三点リーダー: 「……」（2つ連続）が標準
- ダッシュ: 「——」（2つ連続）が標準
- 感嘆符・疑問符の後に全角スペースがあるか
- 括弧の全角・半角混在

#### Part 3: ペーシング分析

全章のテンション・シーン種別・感情軸を分析する。
章ファイルが存在する場合は本文から分析。存在しない場合はプロットから推定（推定値には「※」を付与）。

各章について以下を判定：

**シーン種別**（章の主要な性質を1つ選定）：

| 種別 | テンション目安 | 種別 | テンション目安 |
|------|---------------|------|---------------|
| 導入 | 2〜3 | 対立 | 5〜7 |
| 日常 | 2〜4 | 戦闘 | 7〜9 |
| 訓練 | 3〜5 | 危機 | 8〜10 |
| 準備 | 4〜6 | 決断 | 6〜9 |
| 転換点 | 5〜7 | 告白/開示 | 5〜8 |
| 回復 | 2〜4 | クライマックス | 9〜10 |
| 解決 | 4〜6 | | |

**テンションレベル**（1〜10）

**感情軸の強度**（各0〜5）：
- **緊迫** / **温情** / **恋愛** / **成長** / **喪失** / **希望**

**章の引き**（強/中/弱）

**引きの種類**（疑問型/危機型/転換型/感情型/期待型/なし）
- プロットの「引き:」フィールドと照合し、本文で実現されているか確認する

**問題検出基準：**
- 🔴 **停滞区間**: 同種シーンまたは近テンションの章が3章以上連続（深刻度: 高=4章以上、中=3章でテンション差2以内、低=トーン類似3章連続）
- 🟡 **詰め込み区間**: 隣接章間でテンション差3以上
- 🟠 **引きの弱い章**: 以下のいずれかに該当する章（特に前半で重大）
  - 章末の引きが「弱」または「なし」
  - 日常の延長でそのまま終わっている（「そして眠りについた」「今日も平和だった」等）
  - プロットの「引き:」フィールドで指定された引きが本文で実現されていない
  - 引きの種類が3章以上連続で同じ（引きの単調化）
- 🔵 **感情導線の断絶**: 特定の感情軸が10章以上途切れ
- ⚪ **文字数の偏り**: 平均±30%以上
- 🟤 **文末表現の単調さ**: 章内の文末分布で過去形系（〜た/〜ていた/〜だった/〜なかった）が80%を超えている章。「〜た」「〜ていた」等が4文以上連続している箇所。特に「〜ていた」が1段落に3回以上出現する箇所。（`style-rules.md` E節 参照）
- 🟣 **演出手法の反復**: 以下を検出してカウントする
  - 「手が止まった/止まる/止めた」系の出現回数（部あたり3回以上で指摘）
  - 「心臓が跳ねた/鳴った/高鳴った」系の出現回数（キャラ別にカウント。同一キャラで部あたり2回以上で指摘）
  - 「耳が赤くなった」系の出現回数（同上）
  - 同一の背景動作（カップ磨き等）の出現回数（部あたり4回以上で指摘）
  - ダッシュ「——」による場面転換の出現回数（1章あたり3回以上で指摘）
  - 「〇〇は気づいていない/知らない」系の章末（1回でも指摘。`forbidden-patterns.md` #22）
  （`style-rules.md` G節 / `forbidden-patterns.md` #21〜#23 参照）
- 🔶 **内心モノローグの過剰**: 章あたりの（ ）の個数をカウントし、15個を超える章を指摘。（ ）が4行以上連続している箇所を指摘。（`style-rules.md` F節 参照）
- ⬛ **シーン構造のテンプレート化**: 3話以上が同じ構造パターン（例：時間提示→日常描写→小事件→内心モノローグ→締め）で進行していないか。章の構成要素の順序を比較し、類似度が高い連続章を検出する
- 🟢 **プロース・ダイナミクスの欠如**: クライマックス（テンション7以上）の章で、文末分布・文の平均長・内心モノローグ頻度が日常章（テンション3以下）と有意に異ならない場合に指摘。「プロットは盛り上がっているが、文章のリズムが変わっていない」状態の検出
- 🩵 **キャラクター能動性の欠如**: 主人公（POVキャラ）が章内で「自発的な選択・行動・決断」を1つもしていない章を検出する。以下のパターンに該当する場合に指摘:
  - 主人公が他キャラの行動に反応するだけで、自分から何かを起こしていない（受動的な観察者状態）
  - 主人公の行動が全てルーティン（出勤・通学・食事等）で、物語を動かす意志的行動がない
  - シーンの展開が全て外的要因（他キャラの来訪・事件の発生等）に依存し、主人公の能動的選択がない
  - 判定基準: 章内に「主人公が、やらなくてもいいのに自分の意志でやった行動」が1つもなければ指摘
- 🩶 **五感バランスの偏り**: シーンの描写が視覚のみに偏っている章を検出する。1シーン内で非視覚描写（聴覚・嗅覚・触覚・味覚・温度感覚）が1つもない場合に指摘。worldbuilding.md に五感プロファイルが定義されている場所のシーンでは、プロファイルの活用度も確認する。（`style-rules.md` H節 参照）
- 🔷 **情報密度のリズムの単調化**: 段落内の「身体動作・触感・物音・視覚的事象を描く文」と「内心括弧書き・地の文の解釈文」の比率を測る。3〜5文の段落で内心が出来事の3倍を超える、または5文以上の段落で内心が出来事と等量を超える箇所を検出する。「出来事→解説→出来事→解説」の等間隔配置による単調化や、「最後の一文で止めるべき箇所をその前に全部解説してしまっている」パターンを優先的に指摘する。（`style-rules.md` A-7 参照）
- 🌸 **触感・五感の解説的内面化**: 身体接触・触感・五感的事象を含む段落の直後3段落以内に、視点キャラ複数名分の括弧書き独白（2行以上）が連続しているパターンを検出する。「手首冷却シーン型」「手の重なり後の両側独白型」など、触感の余韻を独白で押しのける配置を指摘する。（`forbidden-patterns.md` #25 参照）
- 🟪 **反射的間投詞の頻発**: 「（あ）」「（やばい）」「（待って）」「（え）」「（えっ）」「（——え）」「（あっ）」のような単独行の反射的間投詞をGrepで全章カウントし、`rules.md` の「反射的間投詞の上限」セクションがあればその上限、なければ `style-rules.md` A-8 の汎用上限（1章3回）を超える章を指摘する。コメディシーンの軽いツッコミは除外可能（章の性質を判定）。
- 🟧 **テーマワード自己貼り直し**（`rules.md` に「テーマワード管理」セクションがある場合のみ実行）: 体現キャラ本人の内心独白でのテーマワード自己ラベリングを Grep + 文脈判定で検出し、1章あたりのB区分超過を指摘する。A区分（外部からの観察・他キャラの呟き・地の文の象徴配置）は保持対象として除外する。（`forbidden-patterns.md` #26 参照）

### ステップ5: 対話による確認

チェック結果を提示した後、ユーザーと対話してください：

- 指摘事項についての質問に回答
- 追加のチェック観点があれば再チェック
- 特定の章を深掘りしたチェック
- 改善例の具体的な提案
- 特定の感情軸に絞った追跡分析（感情導線の詳細分析）

#### check_notes.md への追記確認（必須）

チェック結果についての対話が一段落したら、必ず以下を確認する：

「今回のチェックで気になった点や、今後も継続的に確認したい項目はありますか？ check_notes.md に追記します。（なければスキップ）」

ユーザーが項目を挙げた場合：
1. check_notes.md が存在しなければ新規作成する
2. 既存の check_notes.md に項目を追記する
3. 追記した内容をユーザーに確認する

#### ステップ5-D: チェック項目の管理（モードD選択時）

モードDが選択された場合、以下の手順で check_notes.md を管理する。

1. **現状の表示**: check_notes.md が存在すれば内容を表示。存在しなければ新規作成を伝える
2. **操作の確認**: 追記 / 編集 / 削除 / 全体確認
3. **反映**: ユーザーの指示に従い check_notes.md を更新
4. **繰り返し**: 「他に追加・変更したい項目はありますか？」と確認し、完了まで繰り返す

### ステップ6: 保存（必須）

チェック結果を提示した後、スコープに応じたファイルに保存すること。

**保存先の決定:**
- **スコープA・B・C**: `projects/$ARGUMENTS/check_result.md` に保存
- **スコープC-Part（部単位チェック）**: `projects/$ARGUMENTS/check_result_partNN.md` に保存（例：第1部 → `check_result_part01.md`、第2部 → `check_result_part02.md`）

**保存ルール:**
- チェック結果の提示と同時に、自動的にファイルへ保存する
- ユーザーへの確認は不要（常に保存する）
- AIの説明文（「いかがでしょうか？」等）はファイルに含めないこと
- 既存ファイルがある場合は上書きする
