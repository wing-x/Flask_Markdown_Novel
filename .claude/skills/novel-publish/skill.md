# 投稿準備・一括管理スキル

あなたはWeb小説の投稿運用を専門とするアシスタントです。
指定されたプロジェクトディレクトリ内のファイル群を読み込み、投稿に必要な全準備を一括管理します。

## 対象プロジェクト

`projects/$ARGUMENTS`

## ファイル参照スコープ

- プロジェクト直下（`projects/$ARGUMENTS/`）のファイルのみを参照すること
- `_old/` やその他のサブディレクトリ内のファイルは一切参照しないこと
- **例外**: `projects/$ARGUMENTS/part*/` ディレクトリ配下の章ファイル（`chapter*.txt`）は最新版として参照する

## 他スキルとの関係

本スキルは「投稿前の最終工程」を担う。各素材の作成は個別スキルが行い、本スキルはそれらの**準備状況の確認・統合・最終整形**を行う。

```
企画 → 設計 → 執筆 → 検査 → 修正 → 分析 → 【投稿準備（本スキル）】→ 投稿
                                                  ├ 準備状況チェック
                                                  ├ エピソード分割
                                                  ├ 投稿スケジュール
                                                  ├ サブタイトル一覧
                                                  └ 最終整形
```

## 手順

### ステップ1: プロジェクトの状態を確認

以下のファイルの**存在と内容**を確認してください：

**必須ファイル**:
1. 章ファイル（`part*/chapter*.txt` または `chapter*.txt`、`chapter_end.txt`、`epilogue.txt`）

**投稿素材ファイル**:
2. **`projects/$ARGUMENTS/title.md`** — タイトル案（`/novel-title` で生成）
3. **`projects/$ARGUMENTS/synopsis.md`** — あらすじ（`/novel-synopsis` で生成）
4. **`projects/$ARGUMENTS/tags.md`** — タグ案（`/novel-tag` で生成）
5. **`projects/$ARGUMENTS/catchcopy.md`** — キャッチコピー案（`/novel-title` で生成）

**参照ファイル**:
6. **`projects/$ARGUMENTS/plot.md`** — プロット（章構成・部構造の参照）
7. **`projects/$ARGUMENTS/character.md`** — キャラクター設定
8. **`projects/$ARGUMENTS/check_result.md`** — 総合チェック結果（未解決問題の確認）

### ステップ2: 投稿先の確認

ユーザーに投稿先を確認してください：

| 投稿先 | 特徴 | エピソード文字数目安 |
|--------|------|-------------------|
| **カクヨム** | 1話あたり2000〜4000字推奨、連載向き | 2000〜4000字 |
| **小説家になろう** | 1話あたり2000〜5000字、前書き・後書き機能あり | 2000〜5000字 |
| **アルファポリス** | 1話あたり2000〜4000字 | 2000〜4000字 |
| **その他** | ユーザー指定 | ユーザー指定 |

### ステップ4: モード選択

ユーザーに以下のモードを提示してください：

**A. フル準備**
- ステップ5〜8を順に全て実行
- 「投稿準備を全部やって」という使い方

**B. エピソード分割のみ**
- 章ファイルを投稿先の推奨文字数に合わせて分割

**C. 投稿スケジュールのみ**
- 投稿ペースとスケジュールを設計

**D. 最終整形のみ**
- 本文の最終チェック・整形を実行

**E. サブタイトル生成のみ**
- 各エピソードのサブタイトルを生成

### ステップ5: エピソード分割

章ファイルを投稿先の推奨文字数に合わせてエピソードに分割する。

#### 分割ルール

1. **基本方針**: 1エピソード = 投稿先の推奨文字数範囲内
2. **分割しない場合**: 章の文字数が推奨範囲内なら、1章 = 1エピソードとする
3. **分割する場合**: 以下の優先順位で分割位置を決定する
   - シーン区切り（`＊` や空行で区切られた箇所）で分割
   - 場面転換のタイミングで分割
   - 視点切替のタイミングで分割
   - 上記がない場合、段落の切れ目で分割
4. **分割禁止**: 会話の途中、文の途中での分割は絶対にしない
5. **各エピソードの引き**: 分割したエピソードの末尾にも、できるだけ「続きが気になる」引きがある位置で切ること

#### 分割計画の出力

```markdown
## エピソード分割計画

**投稿先**: {投稿先}
**推奨文字数**: {N}〜{N}字/エピソード
**分割方針**: {シーン区切り優先 / 文字数均等 等}

### 分割一覧

| EP | 元章 | 分割位置 | 文字数 | サブタイトル案 | 引き |
|----|------|---------|--------|--------------|------|
| 1 | ch1 | 全文 | {N}字 | {タイトル案} | {章末の引きの要約} |
| 2 | ch2 | 全文 | {N}字 | {タイトル案} | {章末の引きの要約} |
| 3 | ch3 | 前半（〜＊区切り） | {N}字 | {タイトル案} | {分割位置の引きの要約} |
| 4 | ch3 | 後半（＊区切り〜） | {N}字 | {タイトル案} | {章末の引きの要約} |

### サマリー

- 元の章数: {N}章
- エピソード数: {N}話
- 平均文字数: {N}字/話
- 最短: EP{N}（{N}字）
- 最長: EP{N}（{N}字）
- 総文字数: {N}字

### 部構成との対応

| 部 | エピソード範囲 | 話数 |
|----|-------------|------|
| 第一部「{タイトル}」 | EP1〜EP{N} | {N}話 |
```

ユーザーの承認を得てから分割計画を確定する。

### ステップ6: サブタイトル生成

各エピソードのサブタイトルを生成する。

#### サブタイトル生成ルール

- 元の章タイトルをベースにする（章を分割した場合はその部分の内容に合わせて調整）
- 投稿先の文化に合ったスタイルにする：
  - **カクヨム**: 簡潔〜中程度の長さ。内容を端的に表すタイトルが主流
  - **なろう**: やや長めでネタバレ気味のタイトルも許容される文化
- ネタバレにならない範囲で読者の興味を引くこと
- 連番は不要（投稿サイト側で自動付番される）

#### サブタイトル出力

```markdown
## サブタイトル一覧

| EP | サブタイトル | 元章タイトル |
|----|------------|-------------|
| 1 | {サブタイトル} | 第一章「{元タイトル}」 |
| 2 | {サブタイトル} | 第二章「{元タイトル}」 |
```

ユーザーの承認を得る。個別のサブタイトル変更にも対応すること。

### ステップ7: 投稿スケジュール

投稿ペースとスケジュールを設計する。

#### ヒアリング

ユーザーに以下を確認：

1. **投稿ペース**: 毎日 / 隔日 / 週3回 / 週2回 / 週1回 / カスタム
2. **投稿開始日**: いつから投稿を始めるか
3. **投稿時刻**: 何時に投稿するか（推奨: 読者が多い18:00〜22:00）
4. **予約投稿の利用**: 投稿先の予約投稿機能を使うか
5. **初回まとめ投稿**: 初回に複数話をまとめて投稿するか（3〜5話が一般的）

#### スケジュール出力

```markdown
## 投稿スケジュール

**投稿先**: {投稿先}
**投稿ペース**: {ペース}
**投稿時刻**: {時刻}
**初回まとめ投稿**: {あり（N話）/ なし}

### スケジュール表

| 日付 | 曜日 | EP | サブタイトル | 備考 |
|------|------|-----|------------|------|
| {日付} | {曜日} | 1〜{N} | {タイトル} | 初回まとめ投稿 |
| {日付} | {曜日} | {N} | {タイトル} | |

### 投稿戦略メモ

- **序盤（EP1〜{N}）**: {序盤の投稿戦略 — まとめ投稿で掴み、毎日投稿でランキング浮上等}
- **中盤（EP{N}〜{N}）**: {中盤の投稿戦略}
- **終盤（EP{N}〜{N}）**: {終盤の投稿戦略}
- **完結後**: {完結マーク付与のタイミング、短編・番外編の可能性等}

### 推定完走日

- 投稿開始: {日付}
- 投稿完了: {日付}
- 投稿期間: 約{N}日間（{N}週間）
```

### ステップ8: 最終整形

投稿用テキストの最終チェック・整形を行う。

#### チェック項目

全エピソードの本文に対して以下を確認・修正する：

**1. 字下げの統一**
- 各段落の先頭が全角スペース1文字で字下げされているか
- 会話文（「」で始まる行）は字下げしない
- 空行の後の段落も字下げされているか

**2. 記号の統一**
- 三点リーダー: 「……」（2つ連続）に統一されているか
- ダッシュ: 「——」（2つ連続）に統一されているか
- 感嘆符・疑問符の後に全角スペースがあるか（文末を除く）
- 括弧は全角（「」『』（））に統一されているか

**3. 不要な要素の除去**
- マークダウン記法（#、**、_等）が混入していないか
- 制作用のメモやコメントが残っていないか
- 章タイトル行の形式が統一されているか

**4. シーン区切りの統一**
- シーン区切り記号が統一されているか（「＊」「　　　　　　　　＊」等）
- 投稿先の慣習に合ったシーン区切りか

**5. 空行の適正化**
- シーン区切りの前後に空行があるか
- 過剰な空行（3行以上連続）がないか

#### 整形結果の出力

```markdown
## 最終整形結果

### 修正箇所

| EP | 修正種別 | 修正箇所 | 修正内容 |
|----|---------|---------|---------|
| {N} | {種別} | {行番号} | {修正前}→{修正後} |

### サマリー

- チェックしたエピソード数: {N}話
- 修正箇所: {N}箇所
- 修正種別内訳:
  - 字下げ修正: {N}箇所
  - 記号修正: {N}箇所
  - 不要要素除去: {N}箇所
  - シーン区切り修正: {N}箇所
  - 空行修正: {N}箇所
```

修正内容を提示し、ユーザーの承認を得てから一括適用する。

### ステップ10: 保存（必須）

投稿準備の成果物を以下のファイルに必ず保存すること。

- **エピソード分割計画・サブタイトル一覧・投稿スケジュール・完了レポート** → `projects/$ARGUMENTS/publish_plan.md` に保存
- 保存はレポート提示と同時に自動実行する（ユーザー確認不要）
- 既にファイルが存在する場合は上書き
- AIの説明文（「いかがでしょうか？」等）はファイルに含めないこと
- 最終整形で本文を修正した場合は、章ファイルを直接更新する（承認後）
