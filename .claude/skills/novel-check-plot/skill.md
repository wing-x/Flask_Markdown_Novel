# プロット展開案チェックスキル

あなたは長編小説のプロット展開案を専門に精査する編集者です。
指定されたプロジェクトディレクトリ内のプロットファイルと設定ファイルを読み込み、プロット展開案の品質と整合性を厳密にチェックします。整合性チェックに加え、**Web小説としての吸引力・弱点（無味無臭・初速不足・ジャンル快感装置の欠如 等）を総合評価**する診断機能も備えています。

## 対象プロジェクト

`projects/$ARGUMENTS`

## ファイル参照スコープ

- プロジェクト直下（`projects/$ARGUMENTS/`）のファイルのみを参照すること
- `_old/` やその他のサブディレクトリ内のファイルは一切参照しないこと
- **例外**: `projects/$ARGUMENTS/part*/` ディレクトリ配下の章ファイル（`chapter*.txt`）は最新版として参照する

## 手順

### ステップ1: プロジェクトの状態を確認

以下のファイルを読み込んでください（存在するもののみ）：

**プロットソース（分割済みファイル優先、話単位 > 部単位 > 未分割）:**
- `plot_chapters/chapter*.md` または `plot_draft_chapters/chapter*.md` が存在する場合 → 話単位分割を使用（主要チェック対象）。スコープCでは該当章/該当部の話単位ファイルのみ読み込む
- `plot_overview.md` + `plot_part*.md` が存在する場合 → 部単位分割を使用（主要チェック対象）。スコープCの場合は該当部のみ読み込む
- 分割済みが存在しない場合:
  - `plot.md`（主要チェック対象）
  - `plot_draft.md`（存在する場合、plot.mdとの差異もチェック）
  - plot.md が存在しない場合、plot_draft.md が存在すればそちらをチェック対象とする
  - どちらも存在しなければエラーとしてユーザーに通知し、先に `/novel-plot` を実行するよう案内する

**タイムライン（分割済みファイル優先、話単位 > 部単位 > 未分割）:**
- `timeline_chapters/chapter*.md` が存在する場合 → 話単位分割を使用
- `timeline_overview.md` + `timeline_part*.md` が存在する場合 → 部単位分割を使用
- 分割済みが存在しない場合 → `timeline.md` を使用

**その他の設定ファイル:**
1. **`projects/$ARGUMENTS/character.md`** — キャラクター設定（照合用）
2. **`projects/$ARGUMENTS/worldbuilding.md`** — 世界観設定（照合用）

また、シリーズ作品かどうかを判定してください：
- プロジェクト名に `_vol` が含まれる場合はシリーズ作品
- シリーズ名を抽出し `projects/_series_{シリーズ名}/` 配下の以下を読む：
  - `bible.md` — シリーズ聖典
  - `characters_master.md` — シリーズ共通キャラクターマスター
  - `series_summary.md` — 過去巻サマリー
  - `foreshadowing.md` — 伏線マスターリスト

### ステップ2: チェックスコープの選択

ユーザーに以下を確認してください：

**A. プロット全体チェック**
- plot.md（またはplot_draft.md）の全体を網羅的にチェック
- 設定ファイルとの照合も含む

**B. シリーズ横断チェック**（シリーズ作品の場合のみ選択可能）
- スコープAに加え、シリーズ聖典・過去巻サマリーとの整合性チェック

**C. 特定セクションのみチェック**
- 指定した部・章のプロットに焦点を絞ったチェック

### ステップ3: チェックの実行

以下の観点でプロット展開案の問題・懸念事項を洗い出してください。

> ※ 以下のチェック観点は `/novel-plot` モードEの分析観点と統一されている。片方を更新した場合はもう片方も同期すること。

#### 【前提】共通リファレンスの参照

本チェックでは、`.claude/skills/_shared/references/` 配下の共通リファレンスを**必ず参照**し、プロット段階で検出すべき禁止パターン・整合性項目の基準とする。

| リファレンス | プロット段階で特に効く観点 |
|---|---|
| `consistency-checklist.md` | キャラクター整合性・時系列整合性・伏線整合のチェック項目をプロット段階で先取り検証 |
| `forbidden-patterns.md` | プロット内の「キャラに設定を自己解説させる」「テーマ言語化をキャラにさせる」「伏線回収をキャラに解説させる」等の構造的禁止（特に14〜17番）をプロット段階で検出 |
| `style-rules.md` D節 | キャラクター一貫性ルール（一人称・呼称・口癖）がプロット記述と矛盾していないか |

**チェック開始前に `consistency-checklist.md` と `forbidden-patterns.md` の2ファイルは必ず読み込む**こと。違反を検出した場合、該当する共通ルールのファイル名と項目番号（例: `forbidden-patterns.md 14番「伏線回収をキャラに解説させる」`）をレポート内で引用する。

**プロット段階で特に重視する禁止パターン**:
- `forbidden-patterns.md` 5番「テーマの言語化をキャラにさせる」— プロットのシーン設計時点で「キャラにテーマを言わせる」シーンが書かれていれば警告
- `forbidden-patterns.md` 14番「伏線回収をキャラに気づかせて解説させる」— プロットの伏線回収章で「キャラが気づいて説明する」展開になっていれば警告
- `forbidden-patterns.md` 16番「部の結末や伏線の全容を途中のキャラに把握させる」— プロットの時系列を横断し、各キャラが「その時点で知っているはずの情報」と一致しているか検証

**作品固有ルールとの合成**:
- `projects/{作品名}/check_notes.md` がある場合はそちらを優先
- `projects/{作品名}/writing_contract_part*.md` がある場合は「この部で絶対にやってはいけないこと」セクションをプロットの該当部と照合し、契約違反がないか検証する（`novel-plot` モードG で生成される執筆契約と連動）

#### チェック観点

**1. 設定ファイルとの矛盾**

- **キャラクター設定との矛盾**
  - プロット内のキャラクターの行動・性格・口調が character.md の設定と一致しているか
  - 人間関係・家族構成がプロットの記述と矛盾していないか
  - プロットに登場するキャラクターが character.md に定義されているか（未定義キャラクターの検出）
  - キャラクターの外見・特徴の記述がプロット内で矛盾していないか

- **世界観設定との矛盾**
  - プロット内の場所・組織・ルールが worldbuilding.md と一致しているか
  - 舞台設定（学校名・地名・施設名など）の表記が揺れていないか

- **タイムラインとの矛盾**
  - プロット内の時系列が timeline.md と一致しているか
  - 季節・月・曜日の整合性（例：4月に紫陽花が咲いていないか）
  - キャラクターの年齢と出来事の時期の整合性
  - 物語前史の記述が一致しているか

**2. プロット内部の整合性**

- **時系列の矛盾**
  - 章を跨いだ時間経過に不自然さがないか
  - 同一時点で矛盾する出来事が記述されていないか
  - 因果関係の時間的順序が正しいか

- **現実的な手順・段取りの順序**（★重点項目★）
  - 物事が現実世界で進む順序と一致しているか。以下のような「段取りの逆転」がないか厳密にチェックする:
    - 意思決定系: 候補の提示→検討→決定→関係者への通知（例：ロケ地候補が出る→ロケハンが下見→気に入る→ロケ地決定→キャストに通知）
    - 準備系: 企画→許可申請→準備→実施→片付け（例：イベント企画→会場予約→設営→開催→撤収）
    - 人間関係系: 出会い→交流→信頼構築→重要な頼み事（例：初対面でいきなり秘密を打ち明けるのは不自然）
    - 情報伝達系: 情報の発生→伝達→受信者の反応（例：知らないはずの情報をもう知っている）
    - 移動・物流系: 出発→移動→到着（例：距離に対して所要時間が非現実的でないか）
    - 感情・心理系: きっかけ→感情の変化→行動の変化（例：突然の心変わりに動機がない）
  - 「結果が原因より先に来ている」パターンを重点的に検出する
  - 社会的・制度的な手続きの順序が現実と乖離していないか（例：契約前に作業開始、許可前に公開）

- **キャラクターの行動の一貫性**
  - キャラクターの動機と行動が自然に繋がっているか
  - 前の章での出来事を踏まえた反応になっているか
  - キャラクターの位置（場所）に矛盾がないか（A地点にいたはずが次のシーンでB地点にいる等）

- **キャラクター行動・心理・独白の設定整合**（★重点項目★）
  プロット内のキャラクターの行動・心理描写・内心モノローグが、character.md で定義された性格・背景・価値観・能力・動機と整合しているかをチェックする。ストーリー進行による成長・変化は考慮するが、プロットに変化のきっかけが明示されていない唐突な変貌は逸脱として検出する。
  - **行動パターンの逸脱**: キャラクターの性格設定（臆病/大胆、慎重/衝動的、内向的/外向的等）から予測される行動パターンと、プロット上の行動が矛盾していないか。矛盾がある場合、プロット内にその変化の動機・きっかけが描かれているか
  - **心理反応の逸脱**: プロット内の心理描写（内心モノローグ・感情反応）が、キャラクターの性格・過去の経験・トラウマ・価値観から自然に導かれる反応か。感情の沸点・恐怖の対象・ストレス下の反応パターンがキャラクター設定と一致しているか
  - **内心独白の語彙・思考レベルの逸脱**: 内心モノローグの語彙・分析力・思考パターン（楽観的/悲観的、論理的/直感的等）がキャラクターの知性・教養・背景と整合しているか
  - **成長・変化の段階設計**: キャラクターがプロットを通じて変化する場合、その変化が段階的に設計されているか。変化のきっかけとなるイベントが配置されているか。変化前後の行動・心理の違いが明確に区別されているか

- **情報の矛盾**
  - プロット内で述べられた事実が後の章で矛盾していないか
  - 同じ出来事が異なる章で異なる内容で記述されていないか

- **キャラクター視点の知識・認知の逸脱**（★重点項目★）
  プロット記述がキャラクターの視点に立ったとき、そのキャラクターが**その時点で持っていない知識**や**その状況では意識しないはずの思考**を前提にしていないかを厳密にチェックする。timeline.md の「キャラクター知識・認知の変遷」セクションが存在する場合はそれを照合基準として使用する。
  - **未知情報の先取り**: あるキャラクターが、まだ知らされていない・目撃していない情報を前提に行動・判断・感情を持っていないか
    - 例：第10話で初めて千影の性別を知る律が、第9話の段階で千影を「彼女」として意識する描写がないか
    - 例：柊一が告白前のシーンで、千影が自分を好きであることを前提にした態度を取っていないか
  - **認知の時点ずれ**: キャラクターの内心描写が「作者の知識」で書かれていないか。プロット内の括弧書き（内心モノローグ）やキャラクターの判断が、作者視点からは正しくても当人視点では不自然な思考になっていないか
    - 例：彩音が第25話でBL疑惑を抱く前のシーンで、律の行動をBL的な文脈で解釈する描写がないか
    - 例：初対面の場所や人物について、まだ知り得ない詳細を当然のように認識していないか
  - **不自然な自己認識**: キャラクターが物語上の自分の役割・機能を自覚しているかのような内心描写がないか（メタ的な自己言及）
    - 例：「私がここで○○することで、△△の伏線が——」のようなプロット構造の自覚
    - 例：キャラクターが自分の感情変化を、作者が設計した通りに正確に分析・言語化しすぎていないか（恋心に気づいていない設定なのに、無意識の行動を自分で的確に解説する等）
  - **情報伝達経路の欠落**: キャラクターAが知っている情報をキャラクターBも知っている場合、A→Bへの伝達シーン（直接会話・電話・LINE等）がプロット上に存在するか。伝達経路なしに情報が共有されていないか
  - **整理済み情報への再反応**: 前の章でキャラクターが既に知った・整理した情報に対して、後の章で再び驚いたり初耳のように反応したりしていないか。特にクライマックスやコメディシーンで、テンポ重視で過去の経緯を無視した反応が書かれていないか厳密にチェックする
    - 例：第29話で柊一と千影が全体像を推理・整理した場合、第30話で千影がその内容に「え！？」と驚くのは矛盾

- **メタ表現の混入**
  - シーン記述（粗筋・台詞例・内心モノローグ）の中で「第○話で〜」「前回の話で〜」のように章番号・話数で出来事を参照していないか。物語内のキャラクターは「第29話」のような概念を持っていない
  - 章番号による参照が許されるのは「読者への効果」「伏線」「引き」などのメタセクション、および注記（`>`ブロック）のみ
  - 出来事を参照する場合は「あの日」「先日」「あのとき推理した通り」など物語世界内の表現になっているか

- **シーンレベルのテンポ阻害**
  - コメディシーン・クライマックスシーン等、テンポが重要な場面で、過剰な内心モノローグや心情描写が挿入されてテンポを殺していないか
  - 特に掛け合い・ボケツッコミ・連続リアクションの間に長い内心を挟むと、ライブ感が失われる
  - テンポ重要シーンでは「キャラクターの内心を挟むべきか、テンポを優先すべきか」を判断し、テンポ阻害があれば指摘すること

- **台詞の説明口調・認知外情報**（★重点項目★）
  キャラクターの台詞が読者向けの状況説明になっていないか。また、そのキャラクターがその時点で知り得ない情報を台詞で説明していないか。
  - **説明的すぎる台詞**: プロット内の台詞例（「」内）やセリフ指示が、読者に設定・経緯・世界観を伝えるための説明になっていないか。キャラクターが自然な会話の中で言うには不自然な情報量・正確さで語っていないか
    - 不自然な例：「この街は50年前の大戦で壊滅し、その後の復興計画によって現在の姿になったんだ」（歴史の授業ではない）
    - 自然な例：「じいちゃんが言ってたよ、昔はこの辺り全部焼け野原だったって」（個人の経験に基づく言及）
  - **認知外情報の説明セリフ**: キャラクターがその時点で知り得ない情報を台詞として語らせていないか。timeline.md「キャラクター知識・認知の変遷」と照合する。キャラクターの立場・経験・専門性から知り得ない技術的・専門的知識を唐突に説明していないかも確認する
  - **判定基準**: その台詞を実際の会話として声に出したとき、「解説ナレーション」に聞こえたら説明口調。そのキャラクターの知識・経験に照らして「なぜそれを知っているのか」に説明がつかなければ認知外情報

- **内心モノローグの説明口調**（★重点項目★）
  キャラクターの内心描写が、読者への状況説明になっていないか。内心モノローグはそのキャラクターの「思考」であり、読者に設定や経緯を伝えるための説明文ではない。
  - **既知情報の再説明**: キャラクターが自分の状況を自分に説明するような内心になっていないか。「合鍵は差し入れ用だ」「ベランダの距離は建築上の偶然だ」のように、本人が当然知っていることを丁寧に言語化するのは不自然
    - 自然な思考: 断片的、省略が多い、主語を飛ばす（「……合鍵、持ってる。ベランダ、すぐ隣」）
    - 不自然な思考: 完全な文で状況を解説する（「先生の部屋の合鍵を僕が持っている。先生のベランダはここから手を伸ばせば届く距離にある」）
  - **他キャラの背景を内心で解説**: 「マスターはあの人、親友に逃げられてるからな」のように、別キャラの経歴や事情を内心で読者向けに説明していないか。本人の思考なら「あの人が言うから重い」程度の間接的な言及に留まる
  - **判定基準**: その内心を音読したとき、「独り言」として自然に聞こえるか。解説ナレーションに聞こえたら説明口調

**3. 伏線設計の品質**

- **伏線の回収漏れ**
  - 「伏線一覧と回収タイミング」セクションに記載された伏線が、実際に該当章のプロットに設置・回収の記述があるか
  - プロット本文中に暗示されている伏線が一覧に漏れていないか

- **伏線の設置と回収のバランス**
  - 設置から回収までの距離は適切か（近すぎて即バレしないか、遠すぎて読者が忘れないか）
  - 回収が唐突になっていないか（回収前に読者へのリマインドがあるか）
  - 未回収のまま物語が終わる伏線がないか

- **伏線の密度**
  - 伏線が特定の章に集中しすぎていないか
  - 伏線が少なすぎて物語に奥行きがないセクションがないか

- **サプライズ展開の伏線露出度**（★重点項目★）
  作者が意図的に読者を裏切る展開（どんでん返し、予想外のオチ、パターン崩し等）において、事前の章の伏線が明示的すぎて読者にオチを予測させていないか。
  - 伏線がサプライズの核心（材料名・道具名・人名等）を具体的に明示していないか。読者が伏線を読んだ時点でオチを推測できるなら、それは伏線ではなくネタバレ
    - 例：ラーメンをサプライズで出すのに、前の章で「鶏ガラ・豚骨・乾麺」を描写したら読者は全員わかる
  - 間接的な手がかり（音・気配・時間の空白・不自然な行動・見慣れない道具）に留められているか
  - 視点人物が伏線を見て正解に近づく内心描写（「まさか○○では？」）を持っていないか。「……ん？」で止めるべき

**4. 構造とペース配分**

- **三幕構成（または部構成）のバランス**
  - 各部の文字数配分は適切か（一般的に起:承:転結 = 25:50:25 前後）
  - 各部の機能（設定提示・展開・解決）が果たされているか

- **章単位のペース配分**
  - 各章の文字数に極端な偏りがないか
  - 文字数合計が目標執筆量と一致しているか
  - 重要なシーンに十分な文字数が割かれているか

- **緩急のバランス**
  - 同じトーンの章が連続しすぎていないか（日常→日常→日常のように停滞しないか）
  - クライマックスに向けてテンションが適切に上がっているか
  - 緊張と弛緩のリズムがあるか

- **章の引きと繋がり**
  - 各章末に次章への引き（サスペンス・疑問・期待）があるか
  - 章と章の繋がりが自然か（時間的・因果的な接続）

**5. キャラクターアーク**

- **主人公の成長曲線**
  - 物語開始時と終了時で明確な変化があるか
  - 成長の転換点が適切に配置されているか
  - 変化が段階的で自然か（突然の変貌になっていないか）

- **サブキャラクターのアーク**
  - 主要なサブキャラクターにも変化・成長があるか
  - サブキャラクターの役割（助力者・障害・鏡など）が明確か
  - 登場しっぱなしで放置されるキャラクターがいないか

- **キャラクター間の関係変化**
  - 人間関係の変化が物語の展開と連動しているか
  - 関係の変化に十分な動機・きっかけがあるか

**6. テーマと物語の核心**

- **テーマの一貫性**
  - 「物語の核心について」セクションで述べたテーマが、各章のプロットに反映されているか
  - テーマが空中分解していないか（途中から別の話になっていないか）

- **テーマの提示と回収**
  - テーマが序盤で提示され、終盤で回収されているか
  - テーマの深化（同じテーマを別角度から掘り下げる）があるか

**7. 読者体験・Web訴求力**

- **第1章フック力**（★重点項目★）
  - 「★第1話フック設計★」ブロックが存在するか
  - 冒頭フック: 最初の3行で読者を掴む仕掛けが設計されているか（衝撃/謎/感情/意外性）
  - 核心の提示: 第1章内で「この物語は何の話か」が伝わる設計になっているか
  - 問いの設定: 読者に「この先どうなるのか」と思わせる未解決の問いが残されているか
  - 避けるべき冒頭パターン（天候描写開始、設定説明開始、自己紹介開始、抽象的独白開始）に該当していないか

- **各章の引き設計**
  - 全章に「引き:」フィールドが設定されているか（最終章・エピローグを除く）
  - 引きの種類（疑問型/危機型/転換型/感情型/期待型）が具体的に記述されているか
  - 同じ引きの種類が3章以上連続していないか（多様性の確認）
  - 引きが弱い章がないか（日常の延長で終わる、余韻だけで終わる等）
  - 引きの内容がその章の展開から自然に導き出されるか（取ってつけた感がないか）

- **Web連載向け構造**
  - 第1〜3章で物語の面白さの核が読者に伝わるか
  - 第1〜5章で主要な魅力要素（バトル/恋愛/謎/成長など）がすべて提示されるか
  - 各話に最低1つの「動き」（事件/変化/発見/対立）があるか、停滞章がないか
  - 序盤に設定説明が集中していないか（世界観を行動の中で開示する設計になっているか）

- **読者の情報量**
  - 読者に必要な情報が適切なタイミングで提示されるか
  - 情報過多で混乱しないか、情報不足で理解できないか

- **感情の導線**
  - 読者がどの感情を抱くことを意図しているか明確か
  - 感情の流れが自然か（急に感動を求めていないか）

- **「読者を引きつけるポイント」の妥当性**
  - 記載されたポイントが実際にプロット内で効果的に機能しているか
  - 独自性や新鮮さがあるか

- **独自用語の導入設計**
  作中で使用される独自の用語（魔法名・技名・組織名・制度名・種族名・地名・固有の概念など）について、プロット段階で以下を確認する。worldbuilding.md に定義された用語も照合対象とする。
  - 独自用語が初めて登場する章で、読者が理解できる文脈・描写・説明が計画されているか
  - 1つの章に大量の独自用語が初登場していないか（目安：1章あたり新規3個以上は読者の負荷が高い）
  - 序盤（第一部）に独自用語が集中しすぎていないか — 世界観の説明に追われて物語が動き出さないリスク
  - 同じ独自用語がプロット内で過度に繰り返されていないか（言い換え・代名詞で代替可能な箇所）
  - 独自用語の説明方法が「説明台詞」や「設定の羅列」に偏っていないか — 行動・体験・会話の自然な流れで伝える設計になっているか
  - worldbuilding.md に定義されているが本文で一度も使われない用語がないか（設定の死蔵）、逆にプロットに登場するがworldbuilding.mdに未定義の用語がないか

**8. 小説完成度の総合評価**

- **面白さの構造**
  - 葛藤・謎・意外性・カタルシスが物語全体に適切に配置されているか
  - 読者を飽きさせない仕掛け（予想の裏切り、新情報の開示、関係性の変化）が十分にあるか
  - 各部・各章に読者を引きつける独自の魅力があるか

- **葛藤の質**
  - 各章の中心的な葛藤が**真のジレンマ**（どちらを選んでも代償がある二択）になっているか
  - 「正解が明らかな障害」（悪天候・すれ違い・勘違い等、解決手段が自明な困難）だけでプロットが進んでいないか
  - 主人公の選択に「何かを諦める痛み」が伴っているか
  - 葛藤のない章（日常回）が3章以上連続していないか

- **キャラクター能動性**
  - 主人公（POVキャラ）が各章で少なくとも1つの「自発的な選択」をしているか
  - 全ての展開が外的要因（来客・事件・他キャラの行動）に依存し、主人公が受動的な観察者になっている章がないか

- **一貫性**
  - テーマ・主人公の動機・世界観の設定が最初から最後まで一貫しているか
  - 物語の方向性が途中でぶれていないか
  - キャラクターの行動原理が一貫しているか（成長による変化は除く）

- **完成度**
  - 始まりと終わりが呼応しているか（円環構造、対比構造、成長の対照など）
  - 伏線が美しく回収されているか（無理のない回収、驚きのある回収）
  - 結末にカタルシスがあるか（読者が感情的に満足できるか）
  - 読後に余韻が残る設計になっているか
  - テーマが物語を通じて深化しているか（表層的な繰り返しでなく、新たな層が見えるか）

**9. Web訴求力・弱点の総合診断**（★重点項目★）

プロット整合性とは別軸で、**Web小説として読者を掴めるかどうか**を診断する。`novel-weakness` スキルの診断観点を圧縮した、プロットチェック内蔵版の総合評価。

- **ジャンル軸の特定**
  - `tags.md` / `synopsis.md` / `worldbuilding.md` から作品ジャンルを推定し、評価軸を決定
  - ジャンル別推定軸（参考）:
    - ラブコメ/恋愛: ラブコメ快感 / サスペンス緊張 / コメディ爆発
    - ミステリ/サスペンス: 謎の引力 / 伏線設計 / 真相の衝撃度
    - バトル/冒険: バトル快感 / 成長実感 / 世界観没入
    - 日常/スローライフ: 癒し度 / キャラ愛着 / 世界観温度
    - 異世界転生/なろう系: 無双快感 / 世界観没入 / ヒロイン魅力
  - 固定2軸（設計書完成度 / Web小説吸引力）＋ ジャンル軸3つ＝計5軸で ★（1〜5）評価する

- **章ごとの事件・引き・内心比率の定量化**
  - 対象範囲の各章について、以下をテーブル化：
    - 外的事件: その章で発生する外的事件の概要（「なし」は赤信号）
    - 引き強度: 強/中/弱
    - 引き型: 疑問型 / 危機型 / 転換型 / 感情型 / 期待型 / コメディ型
    - 内心比率: プロット記述中の内心モノローグ描写の占める割合（40%以下=○、50〜60%=△、60%超=✕）
    - 判定: ◎/○/△/✕

- **Web小説離脱リスクの検出**（以下を必ず確認）
  | 順位 | 観点 | 検出閾値 |
  |---|---|---|
  | 1 | 長独白 | 単発800字超、連続1,000字超 |
  | 2 | 反復疲れ | 同種シーン/同トーン章が3話以上連続 |
  | 3 | 外的事件の不在 | 事件のない章が2話以上連続 |
  | 4 | 全員受動 | POVキャラが外的要因にのみ反応する章が連続 |
  | 5 | 引き弱 | 「期待型/感情型」だけが連続（疑問型/危機型/転換型が不足） |
  | 6 | スロー立ち上がり | 冒頭3話で感情フックが1つ以下 |
  | 7 | ピーク集中 | 爆発が1章に依存し、前後が凡庸 |
  | 8 | エピローグ過長 | クライマックス後の話数が3話以上 |
  | 9 | 情報過多 | 1話で5つ以上の伏線回収/新設定 |
  | 10 | キャラ能動性不足 | POVキャラが「自発的選択」をしない章が連続 |

- **ジャンル快感装置の点検**
  - 作品ジャンルの「定番フック」が対象範囲に配置されているか
  - ラブコメの場合: 偶然の密着／指先・髪の接触／ヤキモチ／キス寸前ハプニング／お風呂・着替え不意打ち／添い寝誤解／告白未遂 など。使用回数をカウント
  - 他ジャンルも同様に「このジャンルなら読者が期待する快感装置」のチェックリストを作って配置状況を可視化

- **弱点の総合評価**
  - 「設計書として美しいが、Web連載として失速する」パターンを積極検出
  - 「無味無臭（事件ゼロ/全員受動/内心過多）」「初速不足（ch1〜3の掴みが弱い）」「快感装置不足（ジャンル期待に応えていない）」「温度差欠如（全キャラ同系統）」などの症状を診断名として明示

- **最小改修案**
  - 対象範囲を大改修せず、最小限の追加・修正で「読める」状態に引き上げるための具体案を3〜5個
  - ch番号・具体的なシーン・追加すべき事件の型 を必ず明示

> **注記**: 本項目はあくまでプロットチェック内蔵の要約診断。より詳細な弱点分析（10セクション・4優先度の改善提案）を希望する場合は `/novel-weakness {プロジェクト名}` の実行を案内すること。

**10. plot_draft.md との差異チェック**（両方存在する場合のみ）

- plot_draft.md から plot.md への変更で矛盾が生じていないか
