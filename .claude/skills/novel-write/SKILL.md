# 章本文生成スキル

あなたはプロの小説家として、プロットに基づいて小説の本文を執筆するアシスタントです。
指定されたプロジェクトディレクトリ内の設定ファイルを読み込み、章ごとの本文を生成します。

## 対象プロジェクト

`projects/$ARGUMENTS`

## ファイル参照スコープ

- プロジェクト直下（`projects/$ARGUMENTS/`）のファイルのみを参照すること
- `_old/` やその他のサブディレクトリ内のファイルは一切参照しないこと
- **例外**: `projects/$ARGUMENTS/part*/` ディレクトリ配下の章ファイル（`chapter*.txt`）は最新版として参照する

## 手順

### ステップ1: プロジェクトの状態を確認

#### 1-A. プロットソースの検出（分割済みファイル優先）

まず、分割済みプロットファイルが存在するか確認する。粒度は「話単位」「部単位」「未分割」の3種類があり、**話単位 > 部単位 > 未分割** の優先順位で選択する。

**パターン1（plot.md 系列）:**
- 概要: `projects/$ARGUMENTS/plot_overview.md`
- 部単位: `projects/$ARGUMENTS/plot_part01.md`〜`plot_partNN.md`
- 話単位: `projects/$ARGUMENTS/plot_chapters/chapter01.md`〜`chapterNN.md`

**パターン2（plot_draft.md 系列）:**
- 概要: `projects/$ARGUMENTS/plot_draft_overview.md`
- 部単位: `projects/$ARGUMENTS/plot_draft_part01.md`〜`plot_draft_partNN.md`
- 話単位: `projects/$ARGUMENTS/plot_draft_chapters/chapter01.md`〜`chapterNN.md`

**分割済みファイルが存在する場合（推奨）:**

1. 概要ファイル（`plot_overview.md` または `plot_draft_overview.md`）を読み込む（全体構造・伏線一覧・品質設計等の概要情報）
2. 部別プロット・話単位プロットは**この時点では読み込まない**。ステップ3で生成対象の章が確定した後、以下の優先順位で該当ファイルのみを読み込む:
   - **話単位ファイル（`*_chapters/chapter{NN}.md`）が存在する場合**: そのファイルのみを読み込む（最もコンテキスト効率が良い）
   - **話単位が無く部単位が存在する場合**: 該当部の `*_partNN.md` を読み込む
   - **どちらも無い場合**: 未分割の `plot_draft.md` / `plot.md` から該当章の節を Grep で抽出する
3. 両パターンが存在する場合、`plot_draft_*` 系列（詳細版）を優先する
4. パターン内で粒度が複数存在する場合（例：部単位と話単位の両方が存在）、**話単位を優先**する

**分割済みファイルが存在しない場合:**
- 以下のファイルを確認する:
  1. **`projects/$ARGUMENTS/plot_draft.md`** — プロット展開案・詳細版（優先）
  2. **`projects/$ARGUMENTS/plot.md`** — プロット展開案・簡潔版
- `plot_draft.md`（詳細版）と `plot.md`（簡潔版）の両方が存在する場合 → ステップ3のヒアリングでユーザーに選択させる
- `plot_draft.md` のみ存在する場合 → `plot_draft.md` を使用
- `plot.md` のみ存在する場合 → `plot.md` を使用
- **大規模プロットの警告**: `plot_draft.md` が10万字（100,000文字）を超える場合、以下の警告を表示する:
  「⚠️ plot_draft.md が {文字数}字あり、コンテキストを大量に消費します。`/novel-plot` のモードF（プロット分割）で分割することを推奨します。粒度は『話単位』を選ぶと、1話ずつの読み込みでコンテキスト消費が最小化されます。」
  警告後、ユーザーが続行を選択した場合はそのまま進行する。

plot.md / plot_draft.md / 分割済みファイルのいずれも存在しない場合はエラーとしてユーザーに通知してください。

#### 1-B. その他の設定ファイル

以下のファイルを読み込んでください（存在するもののみ）：

1. **`projects/$ARGUMENTS/character.md`** — キャラクター設定
2. **`projects/$ARGUMENTS/worldbuilding.md`** — 世界観設定
3. **`projects/$ARGUMENTS/writing_contract_partNN.md`** — 部別執筆契約（`/novel-plot` モードG で生成される）
   - 生成対象の章が属する部の契約ファイルのみ読み込む（例：第2部の章を書くなら `writing_contract_part02.md`）
   - 契約ファイルが存在する場合、本文生成時に以下を**絶対に遵守**する：
     - 「この部のゴール」に沿った展開になっているか
     - 「絶対にやってはいけないこと」に抵触していないか（キャラに言語化させない要素・後続部の種明かし・崩してはいけない構造的ルール）
     - 「設置する伏線」「回収される伏線」が該当章で適切に配置されているか
     - 「感情線の到達点」に向けて各キャラが進んでいるか
     - 「禁止表現（作品固有）」を使っていないか
   - 契約ファイルが存在しない場合はスキップ（従来通りプロット・設定ファイルのみに基づいて執筆）

タイムラインも分割済みファイルを優先する（話単位 > 部単位 > 未分割）:
- `timeline_chapters/chapter*.md` が存在する場合 → `timeline_overview.md` のみ先に読み込む。話単位タイムラインは該当話のプロットと一緒に後で読み込む
- `timeline_overview.md` + `timeline_part*.md` が存在する場合 → `timeline_overview.md` のみ先に読み込む。部別タイムラインは該当部のプロットと一緒に後で読み込む
- 分割済みが存在しない場合 → `timeline.md` を読み込む

また、シリーズ作品かどうかを判定してください：
- プロジェクト名に `_vol` が含まれる場合はシリーズ作品
- シリーズ名を抽出し `projects/_series_{シリーズ名}/` 配下の以下を読む：
  - `bible.md` — シリーズ聖典
  - `characters_master.md` — シリーズ共通キャラクターマスター
  - `series_summary.md` — 過去巻サマリー

さらに、既存の chapter ファイルを確認してください：
- `projects/$ARGUMENTS/chapter*.txt`（ルート直下）
- `projects/$ARGUMENTS/part*/chapter*.txt`（部構造がある場合）
- `projects/$ARGUMENTS/epilogue.txt`
- `projects/$ARGUMENTS/chapter_end.txt`

### ステップ2: プロットの章構成を解析

選択されたプロットソース（`plot_draft.md` または `plot.md`）から章構成を抽出し、一覧をユーザーに提示してください。

**注意**: 章構成の解析にはどちらのファイルでも同じ見出し構造（`##`, `###` 等）を使用しているため、解析ロジックは共通です。

部構造（`## 第一部`, `## 第二部` など）がある場合はそれも含めて表示します。

表示例：
```
プロットソース: plot_draft.md（詳細版）

章構成：
- 第一部「いつもの距離」
  - 第1章「春風と卵焼き」
  - 第2章「妹の門番」
  - 第3章「転校生の微笑み」
- 第二部「揺れる距離」
  - 第4章「嘘と本音」
  - 第5章「雨の放課後」
  - 第6章「文化祭前夜」
- 第三部「ゼロ距離」
  - 第7章「蓮の気づき」
  - 第8章「卵焼きの味」
  - 第9章「隣の席の幼馴染」
- 結末

既存ファイル: chapter01.txt, chapter02.txt（生成済み）
```

### ステップ3: ヒアリング

ユーザーに以下を確認してください：

0. **プロットソースの選択**:

※ 分割済みファイル（話単位 `*_chapters/chapterNN.md`、または部単位 `*_partNN.md` + `*_overview.md`）が存在する場合は自動的にそちらを使用し、この選択は省略する

| ソース | 説明 |
|--------|------|
| **話単位プロット**（自動選択・最優先） | 概要ファイル + 該当話の `*_chapters/chapterNN.md` のみ読み込む。**コンテキスト効率が最も高い**（1話あたり約1,500 tokens） |
| **部単位プロット**（自動選択・話単位が無い場合） | 概要ファイル + 該当部の `*_partNN.md` を読み込む。コンテキスト効率が高い |
| **plot_draft.md（詳細版）**（推奨） | シーンごとの詳細な展開、代表的な台詞例、内心描写、読者への効果、伏線メモ等を含む。情報量が多く、執筆時の情報欠落が少ない |
| **plot.md（簡潔版）** | 章ごとの粗筋を簡潔にまとめた版。情報は圧縮されており、執筆時に自由度が高い反面、プロットの意図が欠落するリスクがある |

※ `plot_draft.md` のみ存在する場合は自動的に `plot_draft.md` を使用し、この選択は省略する
※ `plot.md` のみ存在する場合は自動的に `plot.md` を使用し、この選択は省略する

以降のステップでは、ここで選択されたプロットソースを「プロット」と呼ぶ。

1. **生成モード**: どの章をどのように生成するか

| モード | 説明 | 保存方式 |
|--------|------|----------|
| **A. 単発生成** | 特定の章を指定して生成（例：「第3章」「第5章と第6章」） | 逐次確認 |
| **B. 連続生成** | 指定した章から最終章まで自動で連続生成 | 自動保存（章ごと即時保存） |
| **C. 全章一括生成** | 第1章から最終章まで一括生成 | 逐次確認 or 一括確認 |
| **D. 未生成のみ** | 未執筆の章を自動検知して生成 | 自動保存（章ごと即時保存） |
| **E. 部単位生成** | 指定した部の全章を生成（例：「第2部」「第1部と第3部」） | 自動保存（章ごと即時保存） |

2. **文体の選択**:

| 文体 | 説明 | 向いているジャンル |
|------|------|-------------------|
| **標準** | 現代的で読みやすい文体 | ライトノベル・一般文芸 |
| **文学的** | 格調高く重厚な文体 | 純文学・歴史小説 |
| **ライト** | 軽快でテンポの良い文体 | エンタメ・ラブコメ |
| **コメディ** | ツッコミ・ボケのテンポを重視した文体 | ギャグ・コメディ・ラブコメ |
| **ドラマチック** | 感情表現が豊かで劇的な文体 | ファンタジー・アクション |
| **硬派** | 硬質で冷静な文体 | ミステリー・SF |
| **詩的** | 叙情的で美しい文体 | 恋愛小説・ファンタジー |
| **フェチズム特化** | 体の細部・所作・布越し・陰翳に偏執的な視線を注ぐ谷崎・川端系の文体。直接描写を避け、視線・温度・影で間接的に官能を立ち上げる | 耽美・文学的官能・大人向け恋愛 |

3. **確認方法**（モードA・Cの場合のみ）:
   - **逐次確認**（デフォルト）: 各章生成後に内容を確認してから保存
   - **一括確認**: 全章生成後にまとめて確認・保存（時間短縮）

#### モードB「連続生成」の詳細

連続生成モードはコンテキスト制限による中断からの再開を想定した機能です。

**開始章の決定:**
- ユーザーが開始章を指定した場合はその章から開始
- 指定がない場合は、既存の chapter ファイルを走査し、**最後に生成済みの章の次の章**を自動検出して提案する
  - 例：chapter01.txt〜chapter05.txt が存在する場合 →「第6章から再開しますか？」

**連続生成の動作:**
1. 指定された開始章から最終章（または結末・エピローグ）まで順番に生成する
2. **各章はファイルに保存した直後に、ステップ4.5の文字数検証・自動加筆ルーチンを実行する**
3. 検証通過後、次の章の生成に進む前に、生成した章のタイトルと文字数を1行で報告する
4. 直前に保存した章の内容を読み込んでから次の章を生成する（章間の連続性を確保）
5. 全章完了まで中断なく進行する

**中断と再開:**
- コンテキスト制限やセッション切断で中断した場合、ユーザーは再度 `/novel-write` を実行する
- 既存ファイルを走査し、中断箇所から自動再開を提案する
- 文体設定は再度ヒアリングする（前回の設定は保持されない）

**既存ファイルの扱い:**
- 開始章以降に既存ファイルがある場合、上書きするか確認する（開始前に一度だけ確認）
- 開始章より前の既存ファイルには触れない

#### モードD「未生成のみ」の詳細

未生成のみモードは、歯抜けになっている未執筆章を自動検知し、それらだけを生成する機能です。
モードC（全章一括生成）やモードB（連続生成）がコンテキスト制限で中断した場合の復旧に最適です。

**未執筆章の自動検知:**
1. plot.md の章構成（部構造を含む）から、全章のファイルパスの期待値リストを生成する
   - 例：第一部・第1章 → `part01/chapter01.txt`、結末 → `chapter_end.txt`
2. 実際に存在するファイルを走査し、期待値リストと照合する
3. ファイルが存在しない章を「未執筆章」として抽出する

**検知結果の提示:**
未執筆章の一覧をユーザーに提示する。

表示例：
```
未執筆章の検知結果:
  生成済み: 45章
  未執筆:   35章 + 結末

未執筆章の一覧:
  第三部: 第34章「章タイトル」, 第35章「章タイトル」, 第36章「章タイトル」
  第四部: 第47章「章タイトル」〜第52章「章タイトル」（6章）
  第五部: 第61章「章タイトル」〜第80章「章タイトル」（20章）
  結末

生成を開始しますか？
```

**生成の動作:**
1. ユーザーの承認を得たら、未執筆章を章番号順に生成する
2. **各章はファイルに保存した直後に、ステップ4.5の文字数検証・自動加筆ルーチンを実行する**
3. 検証通過後、次の章の生成に進む前に、生成した章のタイトルと文字数を1行で報告する
4. **章間の連続性確保**: 未執筆章の直前の章（生成済みファイル）を読み込んでから生成する
   - 例：第34章が未執筆で第33章が生成済みの場合、第33章を読んでから第34章を生成
   - 連続する未執筆章の場合、直前に生成した章の内容を引き継ぐ
5. 全未執筆章が完了するまで中断なく進行する

**既存ファイルの扱い:**
- 生成済みファイルには一切触れない（上書きしない）
- 未執筆章のみを対象とする

#### モードE「部単位生成」の詳細

部単位生成モードは、分割済みプロット（話単位 `*_chapters/chapterNN.md` または部単位 `*_partNN.md`）と連動し、指定した部の全章を効率的に生成する機能です。
該当章/部のプロット・タイムラインのみを読み込むため、コンテキスト消費を最小化できます。

**発動条件:**
- 部構造（`# 第N部` 等）がプロットに存在すること
- 分割済みプロットが存在することを推奨（未分割でも動作するが、コンテキスト効率のメリットが薄れる）
- **話単位分割があれば最優先で使用**（1章あたり約1,500 tokens で済むためコンテキスト消費が最小）

**部の指定:**
- ユーザーが部を指定する（例：「第2部」「第1部と第3部」「第3部以降」）
- 指定がない場合は、既存の chapter ファイルを走査し、未完了の部を提案する

**部単位生成の動作:**
1. 概要ファイルの全体構造テーブルから、指定された部に含まれる章番号の範囲を取得する
2. 読み込み方針を決定する（優先順位「話単位 > 部単位」）:
   - **話単位ファイルがある場合（推奨）**: 部別プロットは読み込まず、各章の生成開始時にその章の `*_chapters/chapterNN.md` と `timeline_chapters/chapterNN.md`（存在する場合）のみ読み込む
   - **話単位が無く部単位のみの場合**: 該当部の `*_partNN.md` と `timeline_partNN.md`（存在する場合）を読み込む
3. 該当部の章を第1章から順番に生成する
4. **各章はファイルに保存した直後に、ステップ4.5の文字数検証・自動加筆ルーチンを実行する**
5. 検証通過後、次の章の生成に進む前に、生成した章のタイトルと文字数を1行で報告する
6. 直前に保存した章の内容を読み込んでから次の章を生成する（章間の連続性を確保）
7. **話単位ファイル使用時は、次の章に進むタイミングで前の章の話単位プロットファイルの参照を破棄する**（コンテキストから解放。ステップ3.7の「前の章のプロット節は役目を終えたので参照しない」と同じ運用）
8. 該当部の全章が完了するまで中断なく進行する
9. 複数の部が指定された場合は、部の順番に従って連続で生成する。部単位ファイル使用時は部切替で次の部のプロットを読み込み前の部を解放。話単位ファイル使用時は章単位で読込/解放するので部切替で特別な処理は不要

**章間の連続性確保:**
- 該当部の最初の章を生成する際、直前の部の最終章（生成済みファイル）を読み込む
  - 例：第2部の生成開始時、第1部の最終章 `part01/chapter08.txt` を読み込んでから第9章を生成
  - 直前の部の最終章が未生成の場合は、プロットのみを参考に生成する
- 部内の各章は、直前の章の内容を読み込んでから生成する

**既存ファイルの扱い:**
- 該当部内に既存ファイルがある場合、上書きするか確認する（部の生成開始前に一度だけ確認）
- 指定された部以外のファイルには一切触れない

**複数部の並行生成:**
- ユーザーが2つ以上の部を指定した場合、並行執筆（エージェント活用）の発動条件を満たす。エージェントによる並行生成を使用するかどうかはユーザーに確認する
- 並行生成を使用する場合は「部単位の並行執筆（エージェント活用）」セクションに従う

#### 部単位の並行執筆（エージェント活用）

部構造（`## 第一部`, `## 第二部` など）がある作品で、モードB・C・Dにより複数の部にまたがる生成が必要な場合、**Agent toolを使って部ごとにエージェントを起動し、並行で執筆する**。

**並行執筆の発動条件:**
- 部構造が存在する（`part01/`, `part02/` 等のディレクトリ構造）
- 生成対象の章が2つ以上の部にまたがる
- モードがB（連続生成）、C（全章一括生成）、D（未生成のみ）、E（部単位生成で複数部指定）のいずれか

**並行執筆の動作:**

1. **エージェントの起動**: 生成対象の部ごとに1つのエージェントを起動する。全エージェントを1つのメッセージで同時に起動すること（並列実行）
   - 例：5部構成の全章一括生成 → 5つのエージェントを同時起動

2. **各エージェントへの指示内容**: 以下の情報を全てプロンプトに含める
   - プロジェクトのベースパス
   - character.md の全文（またはキャラクター設定の要約）
   - worldbuilding.md の要約
   - タイムライン: `timeline_chapters/chapter*.md`（話単位・担当部の全話分）または `timeline_partNN.md`（部単位）、なければ `timeline.md` の要約
   - 概要ファイル（`plot_overview.md` or `plot_draft_overview.md`）の概要情報（全体構造・伏線一覧等）
   - 担当する部のプロット: 優先順位「話単位 > 部単位 > 抜粋」。
     - 話単位ファイル（`*_chapters/chapterNN.md`）がある場合: **担当部の各話のファイル全文を章番号順に列挙**
     - 部単位ファイル（`*_partNN.md`）がある場合: その**全文**
     - どちらも無い場合: プロットソースから該当部分を抜粋
   - 文体の指示（ユーザーが選択した文体の執筆指示を全文含める）
   - 出力形式のルール（マークダウン禁止、字下げ、改行ルール等）
   - 分量の目安（3000〜5000字、下限3000字厳守）
   - 文字数検証の手順（Python `len()` で計測、3000字未満なら自動加筆）
   - ファイル保存先のパス（`projects/$ARGUMENTS/part{NN}/chapter{NN}.txt`）

3. **章間の連続性確保**:
   - **部の内部**: エージェント内で章を順番に生成し、直前の章の内容を読み込んでから次の章を生成する
   - **部の境界**: 各エージェントには、担当部の直前の部の**最後の章のファイルパス**を伝える。エージェントは最初の章を生成する前にそのファイルを読み込む。ファイルが存在しない場合（並行生成中で前の部がまだ完了していない場合）はプロットのみを参考に生成する
   - **第一部のエージェント**: 前の部がないため、プロットに基づいて直接生成を開始する

4. **結末（chapter_end.txt）の扱い**: 結末はルート直下に保存するため、最後の部を担当するエージェントに結末の生成も含めるか、全エージェント完了後にメインで生成する

5. **全エージェント完了後の処理**:
   - 全ファイルの文字数を一括検証する（Python `len()` で計測）
   - 3000字未満の章が見つかった場合、メインで加筆を実行する
   - 完了報告（ステップ6）を作成する

**エージェントへのプロンプト例:**
```
以下の小説プロジェクトの第二部（第16章〜第42章）を執筆してください。

【プロジェクトパス】projects/作品名
【保存先】projects/作品名/part02/chapter{NN}.txt

【文体】コメディ
（文体の詳細指示をここに記載）

【キャラクター設定】
（character.md の内容をここに記載）

【全体概要】
（概要ファイル（plot_overview.md / plot_draft_overview.md）の内容、または未分割プロットの概要セクションをここに記載）

【この部のプロット】
優先順位「話単位 > 部単位 > 抜粋」:
- 話単位ファイル（plot_draft_chapters/chapter16.md 〜 chapter42.md）がある場合: 各話のファイル全文を章番号順に列挙
- 部単位ファイル（plot_part02.md / plot_draft_part02.md）がある場合: その全文
- どちらも無い場合: 未分割プロットから第二部の該当部分を抜粋

【この部のタイムライン】
- 話単位（timeline_chapters/chapter16.md 〜）があればその内容
- または timeline_part02.md の内容
- または timeline.md の該当部分

【執筆ルール】
- 1章あたり3200字以上を目標（下限3000字厳守）
- マークダウン記法は一切使用しない
- 各段落の先頭は全角スペース1文字で字下げ
- 1行ごとに空行を入れない。地の文・会話文・短い内心（1〜2行）は空行なしで連続させる（日本語小説の標準フォーマット）
- 場面転換・時間経過（「——翌日。」等）には空行2行を挟む
- 3行以上の連続する内心モノローグ（（）が3行以上）の前後には空行1行
- 10行以上のブロックは内容タイプの切り替わり（地の文→会話等）で空行1行を入れて分割
- 数字は漢数字を使用（❌「173cm」→ ⭕「一七三センチ」、❌「3人」→ ⭕「三人」）。看板・POP等の描写のみ算用数字を許容
- 三点リーダーは「……」（2つ連続）、ダッシュは「——」（2つ連続）
- 読点（、）の密度: 日本語散文として自然な頻度にする（目安: 40〜60字に1読点）。1文中に読点を3個以上入れない。助詞（の・を・に・で・と・へ・から・まで等）の直後に読点を打たない。が/は の後は文が長くなる場合のみ読点を置く。言い淀み（「は、はい」「お、おはよう」等）の読点は必ず保持する
（以下、出力形式のルールを全て記載）

【絶対禁止事項 — これらに違反した章は不合格】
1. メタ記述: 話数番号（「第○話」）を地の文に書かない。「読者だけが知っている」等の第四の壁を破る表現禁止。プロットの「読者への効果」「伏線」セクションの文言を本文に転記しない
2. 視点違反: 各章の視点人物以外の内心描写（括弧書きの心の声、「○○は〜と思った」等）を絶対に書かない。他キャラの感情は外面（表情・仕草・声色）のみで描写する
3. 一人称の混在: character.mdで定義された一人称を全章で統一する。意図的な変化はプロットに明示がある場合のみ
4. Show Don't Tell: 感情を直接名前で書かない（❌「悲しかった」「混乱している」→ ⭕ 身体反応・行動・仕草で表現）。テーマの直接解説禁止（❌「一番たちの悪い嘘だ」→ ⭕ 読者に悟らせる）
5. 表現の反復: 同じ締め表現を2章以上で使い回さない。「心臓が跳ねた」等の同一身体描写を同部内で3回以上使わない。直前の章を読み込んで重複を回避すること
6. 重複行: 同一文や同一段落が連続して2回出現するコピペミスを出さない
7. キャラの立ち位置: 客はカウンターの外、スタッフはカウンターの中。物理的位置を矛盾させない
8. 記号の乱用: 三点リーダー「……」・ダッシュ「——」・読点「、」に頼りすぎない。間や余韻は文の構造・描写で表現する。1文に読点4個以上は要見直し
9. 過度な短文分割: 会話・内心で本来一文の内容を2〜5字の細切れ行に分割しすぎない。意図的演出（衝撃・絶句等）を除き、自然な文の長さを保つ
10. 文末の単調さ: 「〜た」「〜ていた」「〜だった」を4文以上連続させない。4文目は必ず現在形・体言止め・疑問形等の別文末にする
11. 内心モノローグの過剰: 1章の（ ）は15個以下。（ ）3行連続で必ず身体動作を挟む。「（……変なの）」「（……わからない）」系の保留型は原則使わない
12. 演出の使い回し: 「手が止まった」系は1部2回まで。「心臓が跳ねた」「耳が赤くなった」はキャラ固有の身体反応に差し替える。カップ磨きは1部3回まで。場面転換のダッシュ「——」は1章2回まで
13. 「〇〇は気づいていない/知らない」系の締め: 使用禁止。行動描写のみですれ違いを示す
14. 緩急の欠如: クライマックスでは短文・現在形・体言止めに切り替える。コメディは台詞主体でテンポ重視。全場面を同じリズムで書かない
15. シーンの変化義務: 各シーンで感情・関係性・情報・状況・決断のいずれか最低1つが変わること。「何も動かない日常風景」禁止
16. サブテキストの欠如: 感情が強い場面で本音を直接言わせない。話題の回避・非回答・過剰な親切等で間接表現する。「好き」「嫌い」等を台詞で直接言うのはクライマックスのみ
17. 視覚偏重: 1シーンに視覚以外の感覚（聴覚・嗅覚・触覚・味覚・温度）を最低1つ含める

【章間の連続性】
- 第一部の最終章: projects/作品名/part01/chapter15.txt を最初に読み込んでから第16章を生成すること
- 各章は直前の章を読み込んでから生成すること

【品質検証 — 各章保存前に必ず実行】
1. 文字数検証: python -c "print(len(open('ファイルパス', encoding='utf-8').read()))" で3000字以上を確認
2. メタ記述チェック: 生成した本文に「第○話」（タイトル行除く）、「読者」、プロット用語が含まれていないか確認
3. 視点チェック: 視点人物以外の内心描写がないか確認
4. 重複行チェック: 同一文の連続重複がないか確認
5. 算用数字チェック: 本文中に算用数字が混入していないか確認
問題があれば修正してから保存すること。

各章の生成後、タイトルと文字数を1行で報告すること。
```

**注意事項:**
- エージェントは `run_in_background: true` で起動し、メインは全エージェントの完了通知を待つ
- エージェントのモデルは特に指定しない（デフォルトを使用）
- 各エージェントのプロンプトにはプロットの該当部分を**全文**含めること（エージェントはファイルを読めるが、プロンプトに含めた方が確実）
- ステップ3でユーザーが選択したプロットソース（`plot_draft.md` または `plot.md`）の該当部分を含めること

### ステップ3.5: 該当章/部のプロット読み込み（分割済みプロット使用時）

**分割済みプロットを使用している場合のみ実行する。** 未分割の plot_draft.md / plot.md を使用している場合はスキップ。

ステップ3で生成対象の章が確定した後、**話単位 > 部単位 > 未分割** の優先順位で、必要最小限のプロットファイルのみを読み込む。

#### 3.5-1. 読み込むファイルの決定

**話単位ファイル（`*_chapters/chapter{NN}.md`）が存在する場合（最優先・推奨）:**
- 生成対象の章に対応する `plot_draft_chapters/chapter{NN}.md`（または `plot_chapters/chapter{NN}.md`）のみ読み込む
- 部別プロット（`*_partNN.md`）は**読み込まない**（話単位ファイルに必要な情報が含まれている）
- 前後関係の参照が必要な場合のみ、概要ファイルの「部別の流れ」セクションを参照する
- **コンテキスト効率が最も高い**（1話あたり1,000〜2,000 tokens 程度に抑えられる）

**話単位ファイルが無く、部単位ファイル（`*_partNN.md`）が存在する場合:**
- 生成対象の章が属する部の部別プロットファイルを読み込む
- 章→部のマッピング: 概要ファイルの「全体構造の概観」テーブルから、各部に含まれる章番号の範囲を取得し、生成対象の章番号がどの部に属するかを判定する

**どちらも無い場合:**
- 未分割プロット（`plot_draft.md` / `plot.md`）から該当章の節を Grep で抽出する（ステップ3.7の手順に従う）

#### 3.5-2. 読み込む範囲の決定ルール（モード別）

**話単位ファイルを使用する場合（最優先パス）:**
- **モードA（単発生成）**: 指定された章の話単位ファイルのみ読み込む
- **モードB（連続生成）/ モードE（部単位生成）/ モードD（未生成のみ）**: **1章書くごとに、その章の話単位ファイルだけを読み込む**。前の章の話単位ファイルはコンテキストから解放する（次の章に進むタイミングで参照しない）。これにより章数に関係なくコンテキストが蓄積しない
- **モードC（全章一括）/ エージェント並行執筆**: 各エージェントに該当章の話単位ファイルの内容を渡す

**部単位ファイルを使用する場合（話単位が無いフォールバック）:**
- **モードA（単発生成）**: 指定された章が属する部のみ読み込む。複数の部にまたがる場合は該当する全部を読み込む
- **モードB（連続生成）**: 開始章が属する部から読み込み、部が切り替わるタイミングで次の部を読み込む（前の部はコンテキストから解放される）
- **モードC（全章一括）/ モードD（未生成のみ）**: 並行執筆（エージェント活用）を使用する場合、各エージェントに該当部の部別プロットファイルの内容を渡す
- **モードE（部単位生成）**: 指定された部の部別プロットファイルのみを読み込む。複数部を順次生成する場合は、部が切り替わるタイミングで次の部を読み込み、前の部はコンテキストから解放する

#### 3.5-3. タイムラインの分割読み込み

同じ優先順位（話単位 > 部単位 > 未分割）で読み込む:
- `timeline_chapters/chapter{NN}.md` が存在する場合 → 該当話のタイムラインファイルのみ読み込む
- `timeline_partNN.md` が存在する場合 → 該当部のタイムラインファイルを読み込む
- 存在しない場合は `timeline.md`（未分割）を使用する

### ステップ3.7: 章ごとのプロット該当節の絞り込み（全モード必須・最重要）

**このステップはステップ4の執筆の直前に、生成する全ての章について個別に必ず実行する。**
モード（A/B/C/D/E）や単話/連続/部単位の区別を問わず、**1章書くごとに1回、該当章の節だけを改めてコンテキストに再掲示する**。これを怠るとプロットと本文が乖離するため、省略は禁止。

#### 目的

部別プロットファイル（`plot_draft_partNN.md` 等）は数万字〜10万字規模になることがあり、コンテキストに入れていても章生成時にモデルの注意が分散する。話単位ファイル（`*_chapters/chapterNN.md`）を使用している場合でも、ステップ3.5で該当話ファイルをそのまま読み込むため、**必ず契約宣言を行い該当節をコンテキスト先頭に再掲示する**（話単位ファイルの場合、抽出作業は不要でファイル全文がそのまま節になる）。特に連続生成・部単位生成では、章を重ねるごとに「どの章のどのシーンを今書いているか」の焦点が薄れ、以下のような致命的逸脱が発生する：

- **視点違反**（プロット指定の視点人物を無視して別人視点で書く）
- **登場人物の取り違え**（同一キャラを別キャラとして描写する。姓と名を別人扱いする等）
- **シーン構造の改変**（プロットに無いオリジナル展開を挿入する／プロットのシーンを飛ばす）
- **登場キャラの混入**（該当章に登場しないはずのキャラを登場させる）

これらを防ぐため、各章の執筆直前に、該当章の節だけを抽出してコンテキスト先頭に再掲示する。

#### 手順

**手順1: 該当章の節をプロットから抽出する（Grep ベース）**

プロットソースから、生成対象の章の節を抽出する。ソースは優先順位「話単位 > 部単位 > 未分割」で決まる:

- **話単位ファイル使用時**: `*_chapters/chapter{NN}.md` の全文がそのまま該当章の節。抽出不要。ファイル内容をそのまま「【今から書く章のプロット・絶対遵守】」として扱う
- **部単位ファイル使用時**: `plot_draft_partNN.md` or `plot_partNN.md` から下記の手順で該当章を抽出
- **未分割ファイル使用時**: `plot_draft.md` or `plot.md` から下記の手順で該当章を抽出

部単位・未分割ファイルからの抽出手順:
1. 見出しパターン `### 第N話「タイトル」` を探す（`### 第N章` 等の表記ゆれにも対応）
2. 該当見出しの開始行から、次の `### ` が現れる直前の行までを抽出する
3. 抽出したテキストを「【今から書く章のプロット・絶対遵守】」というラベル付きで**必ず自分のコンテキスト上に再表示する**（Readツールでオフセット指定して該当範囲だけ読む、または既にコンテキストにあるなら本文生成直前に自分で再引用する）

**手順2: 該当章の契約を宣言する（自己拘束）**

抽出したプロット節から以下を読み取り、本文生成の直前に**必ず明示的に宣言する**。宣言はチャットに出力する（ユーザーに見せる）形で行うこと。心の中で済ませてはならない：

```
【第N話の執筆契約】
- 章タイトル: 「〇〇」
- 視点人物: 〇〇（プロットの「**視点**:」行から抽出。複数ある場合は順序と切替ポイントも明示）
- 登場キャラ: △△, □□, ××（プロット該当節に登場するキャラのみ。character.md と照合して正式名称で記載）
- シーン構成: シーン1「〜」→シーン2「〜」→シーン3「〜」→引き（プロットの見出し順に列挙）
- 引きの型: 〇〇型（プロットの「**引き**:」フィールドから抽出）
- 章末の締め方: 視点人物の〇〇の行動・感覚・内心で締める（章末予告ナレーション・「読者は知っている」系の全知視点文は絶対に書かない）
- この話時点で登場済みの設定要素（プロット配置表から抽出）:
  - メニュー: △△, □□（この話時点で既に提供されているメニューのみ。未登場メニューの先行描写は禁止）
  - キャラ: △△, □□（この話時点で既に登場したキャラのみ。後の話で初登場予定のキャラを背景にも出さない）
  - 設定アイテム: △△（この話時点で既に導入された設定のみ）
- 絶対に書かないもの:
  - プロット該当節に登場しないキャラの新規登場
  - プロットに無いシーン・オリジナル展開の追加
  - 視点人物以外の内心描写
  - プロットの「シーン順序」を入れ替える・飛ばす
  - **章末の全知視点ナレーション・次章次部予告**（「読者だけが知っている」「第二部で〜動き始める」等）
  - **時系列未出の設定要素の先行描写**（後の話で初登場するメニュー・キャラ・アイテムを背景描写にも出さない）
  - **キャラの台詞口癖の地の文浸透**（台詞「うちのブレンドだ」は維持、地の文は「ブレンド」と中立的に）
```

**手順3: キャラ同一性の事前確認**

「登場キャラ」欄に書いたキャラを、`character.md` の登場キャラ名と照合する：

- **姓・名・フルネーム・愛称・呼称**が同一キャラとして紐づいているかを確認する
- 例：`character.md` に「真白 千影（ましろ ちかげ）」と定義されているキャラは、プロット内で「千影」「真白」「真白千影」等どの呼称で登場しても**同一人物**として扱う
- 別キャラと誤認するリスクがある場合は、契約宣言に `- 呼称統一: 真白千影 = 千影（同一人物）` のように明記する

**手順4: プロット該当節の再表示**

手順1で抽出したプロット該当節を、本文生成の直前にコンテキスト上に再引用する：

```
【今から書く章のプロット・絶対遵守】
### 第N話「タイトル」
（プロット該当節をそのまま全文引用）
---
```

この再引用を行った直後に、ステップ4の本文生成に進む。

#### 連続生成・部単位生成での扱い

- **モードB（連続生成）/ モードE（部単位生成）**: **1章書き終えて次の章に進む時、必ず再度このステップ3.7を実行する**。前の章のプロット節は役目を終えたので参照しない。新しい章の節だけを絞り込む
- **モードD（未生成のみ）**: 未執筆章のリストから1章取り出すたびに、このステップを実行する
- **モードC（全章一括）/ エージェント並行執筆**: 各エージェントに渡すプロンプトに、そのエージェントが担当する各章のプロット該当節を**章ごとに個別に**含める（部全体のプロットだけでは不十分）

#### 失敗の兆候（執筆後の自己点検）

本文生成後、以下のいずれかが発生していたら、このステップの実行が不十分だった証拠。**即座に章を破棄して再生成すること**：

- プロットで指定された視点人物と本文の視点が異なる
- プロットに登場しないキャラが本文に登場している
- プロットのシーンが1つ以上欠落している、または順序が入れ替わっている
- 同一キャラを別キャラとして描写している（姓と名を別人扱いする等）

### ステップ4: 章本文の執筆

#### 【大前提】この skill の唯一の原則 — 本文はプロットから作る、プロットは本文のために在る

この skill における**唯一にして最大の原則**は、「**本文はプロットから生成される**」ということである。
プロットは執筆の参考資料ではなく、**執筆の設計図そのもの**である。プロットに書かれていることが全てであり、プロットに書かれていないことは書かない。プロットは本文の上位に立つ。本文はプロットの下僕である。

この原則に違反する執筆は、どれほど文章が上手でも、どれほどキャラクターが魅力的に描けていても、**全て不合格**である。品質検証を通過しても、プロットから逸脱していれば即座に再生成の対象になる。

以下に続くルールは、この原則を守るための具体的手段である。ルールの文言を機械的に守るのではなく、**「今書こうとしている一文は、プロットのどの箇所から生まれているか」を常に自問しながら書く**こと。プロットに根拠がない一文は書かない。

#### 執筆の最重要ルール

1. **プロットへの絶対忠実性（唯一最優先・他の全てに先立つ）**

   執筆するにあたって、プロットこそが全ての源泉である。以下は交渉の余地のない絶対ルール：

   - **プロットに書かれた出来事・シーン・セリフの要点は、1つ残らず必ず描写すること**。「尺の都合で省略」「描写の都合で別シーンに統合」「表現の都合でカット」は一切許されない
   - **プロットのシーンの順序を絶対に守り、場面を飛ばさないこと**。プロットの `**シーン1**` から `**シーンN**` までを、プロットに書かれた順番通りに描写する
   - **プロットの「視点」指定に絶対に従うこと**。プロットに `**視点**: 彩音（メイン）→律` と書かれていれば、章の前半は彩音視点、後半は律視点で書く。プロットが「彩音視点」と指定した章を律視点で書くことは、どれほど良い動機があっても不合格
   - **プロットに書かれていない大きな展開・シーン・キャラクターを追加しないこと**。思いついたアイデア・面白そうな展開・キャラの掘り下げは、プロットに書かれていなければ**全て不採用**。プロットに書かれていない登場人物を本文に出すことは最も重い違反
   - **プロットに登場しないキャラクターを本章に登場させないこと**。プロット該当節に「柊一・千影・彩音」の3人しか登場しないなら、本文に「律」や「真白（＝千影の姓を別キャラとして扱うような誤解）」を出してはならない
   - **プロット該当節のキーセリフはできる限り原文に近い形で本文に反映すること**。プロットに `「俺は嘘つきが嫌いだ」` と書かれていたら、本文でも `「俺は嘘つきが嫌いだ」` とそのまま使う。勝手な言い換えで意味が変わることを防ぐ
   - **プロットの「読者への効果」「伏線」「設計意図」セクションに書かれた構造的な意図は、本文の中で読者が感じ取れるように間接的に実現すること**。ただし、これらのセクションの文言そのものを本文に転記してはならない（メタ記述禁止）
   - **プロットの記述と自分の執筆判断が衝突した場合、常にプロットを優先すること**。自分の判断を正当化するためにプロットを曲げてはならない

   **プロットに反した本文は、文学的に優れていても失敗作である。** この一点に妥協はない。

   - **メタ記述の絶対禁止（最重要）** — `forbidden-patterns.md` #15 / #18 参照
     - プロットの「読者への効果」「伏線」セクションの文言を本文に転記しないこと
     - 話数番号（「第24話」「第6話」等）を地の文に書かないこと。内容で示すこと（例：❌「第24話の不在」→ ⭕「あの三日間の不在」）
     - 「読者だけが知っている」「読者にはわかる」等の第四の壁を破る表現は禁止。全知視点ナレーションは「誰も気づいていない」等にすること
     - **章末の予告ナレーション禁止（最重要）**: 「第二部で、この店は壊れるように動き始める」「やがて〜が起こる」「この嘘はいずれ〜」のような、次巻・次部・次章の展開を全知視点で予告する文を章末に入れないこと。章末は視点人物の行動・感覚・内心で締める。予告的な効果が必要なら視点人物の違和感・予感として内面から書く
     - **章末の「読者は知っている」系ナレーション禁止**: 「——しかし読者は知っている。〜」「読者だけが、それを知っている」のように、作者が読者に直接語りかけて勘違い構造の種明かしをする文は絶対禁止。読者は本文を読んで自分で気づくもので、作者が解説するものではない
     - 「character設定上では」「プロットによると」等のメタ発言は禁止
     - プロットの構造メモ（「ここが伏線」「ここで回収」等）を本文に混入させないこと
     - **検証手順**: 章末の最後の3段落を読み返し、「読者」「第N部で」「やがて」「まもなく」「後に」等の全知視点語が含まれていないか確認する。含まれていたら該当段落を削除するか、視点人物の内面描写に置き換える

   - **時系列未出の設定要素の先行描写禁止** — `forbidden-patterns.md` #19 参照
     - 連載小説では設定要素（メニュー・キャラ・アイテム・イベント）が時系列に沿って段階的に導入される。後の章で誕生・登場する要素を前の章の背景描写でさらっと出してはならない
     - 「登場」だけでなく「言及」もこのパターンに含まれる（例: 第10話で誕生するメニューを第9話の背景で「誰かが注文している」と書く）
     - 執筆前にプロットの配置表（メニュー配置表・キャラ登場表・イベント配置表）を確認し、「この話時点で既に登場した要素」のリストを頭に入れること
     - 背景描写で登場要素に触れる際は、そのリスト内のものだけを使う。背景の常連の注文内容・店内の備品・話題の出来事すべてに適用される

   - **キャラの台詞の口癖・言い回しを地の文に引き込まない** — `forbidden-patterns.md` #20 参照
     - キャラ固有の言い回し（「うちのブレンド」「俺様」等）は台詞では自然でも、地の文に書くと三人称視点の中立性が崩れる
     - 台詞「うちのブレンドだ」は維持、地の文「ブレンドを注いだ」と書き分けること
     - 特に店主・主人公格のキャラの口癖ほど地の文に漏れやすいので注意
     - 地の文中に一人称代名詞（「うち」「我が」等）やキャラ固有の言い回しが出ていないか、執筆後に確認すること

2. **キャラクター設定の厳守**
   - 外見情報（目の色、髪型・髪色、身長、特徴的な外見など）を**絶対に変更しない**こと
   - 人間関係・家族構成を矛盾させないこと
   - 口癖・癖・性格を反映すること
   - **一人称・呼称の厳守**:
     - character.md で定義された一人称（僕/俺/私/わたし等）を**絶対に変更しない**こと。全章を通じて統一すること
     - 物語中で意図的に一人称が変化する場合は、プロットに明示されている場合のみ許容。その場合も地の文で変化の理由を描写すること（例：「僕、と言った。いつもは俺なのに、この人の前だと自然にそうなる」）
     - キャラクター間の呼称（「マスター」「先生」「千影さん」等）は設定通りに統一し、地の文と台詞で一貫させること
   - **キャラクターの立ち位置・役割の厳守**:
     - 客はカウンターの「外」、スタッフはカウンターの「中」。物理的な位置関係を矛盾させないこと
     - キャラクターの職業・立場に応じた行動をさせること（客がコーヒーを淹れる、スタッフが客席に座る等の矛盾を防ぐ）
   - **キャラクターの行動・心理・独白の設定整合**:
     - キャラクターの行動がcharacter.md の性格・価値観・能力設定から自然に導かれること。臆病な設定のキャラクターが脈絡なく大胆な行動を取ったり、冷静な設定のキャラクターが根拠なく取り乱したりしないこと
     - 心理描写（感情反応・恐怖・怒りの沸点・ストレス下の反応パターン）がキャラクターの性格・背景・トラウマ設定と整合すること
     - 内心独白の語彙・思考パターン（楽観的/悲観的、論理的/直感的等）がキャラクターの知性・教養・性格と整合すること。口調が乱暴な設定なのに内心が丁寧語になったりしないこと
     - ストーリー進行による成長・変化は許容するが、変化のきっかけとなるイベントがプロットに明示されている場合のみ。プロットにない唐突な変貌は禁止
   - **キャラクターの認知・知識の時点整合**:
     - 描写は常に「その時点でそのキャラクターが知っていること・見えていること」に基づくこと
     - 初めて訪れる場所を詳細に把握しているかのような描写は禁止。初見の場所は探索・観察・驚き・戸惑いを伴う描写にすること（例：❌「精密に整備された格納庫に足を踏み入れた」→ ⭕「足を踏み入れた先には、見たこともない規模の格納庫が広がっていた」）
     - 初対面のキャラクターの性格・内面・過去をまだ知らないはずの視点人物が語らないこと
     - まだ起きていない出来事や、知り得ない情報を前提にした行動・判断をさせないこと
     - 設定ファイル（character.md, worldbuilding.md）の情報は**作者の知識**であり、キャラクターの知識ではない。キャラクターがその情報をいつ・どのように知るかを意識して描写すること

3. **出力形式のルール**
   - マークダウン記法は**一切使用しない**（#見出し、**太字**、_斜体_などは使わない）
   - 通常の小説形式で出力すること
   - 各段落の先頭は全角スペース1文字で字下げすること（例：「　彼は立ち上がった。」）
   - 章タイトルは通常のテキストとして記述すること（例：「第一章　出会い」）
   - 本文のみ出力すること（前置き・後置きの説明は一切不要）
   - **改行・空行のルール（日本語小説の標準フォーマット）**:
     - **基本原則: 1行ごとに空行を入れない。** 地の文・会話文・短い内心モノローグ（1〜2行）は空行なしで連続して書く。これが日本語小説の標準フォーマットである
     - 地の文の段落（全角スペース字下げ）、会話文（「」）、短い内心（（））はひとつの「ブロック」として途切れなく流れる
     - **空行を入れる箇所（これ以外では空行を入れない）**:
       - 章タイトルの直後: 空行2行（場面転換扱い）
       - 場面転換・視点切替・時間経過（「——翌日。」等の時間・場所の移動）: 空行2行
       - 3行以上の連続する内心モノローグ（（）が3行以上続く場合）の前後: 空行1行
       - ブロックが10行以上になった場合、内容タイプの切り替わり（地の文→会話、会話→地の文等）で空行1行を入れて分割する
     - **禁止パターン**:
       - ❌ 地の文の1行ごとに空行を挟む
       - ❌ 会話文の前後に毎回空行を入れる
       - ❌ 内心モノローグの1行ごとに空行を入れる
       - ❌ 全ての段落を空行で区切るWeb小説風の改行
     - **良い例**:
       ```
       　男はカップを置いて、顔だけこちらに向けた。
       「面接か」
       「あ、はい。真白千影です」
       　——声が上ずった。
       　慌てて、低く戻す。
       （危ない）
       （今日は男装モードなのに、初手でボロ出すところだった）
       　男はカウンターを出てきて、二人掛けのテーブル席を指で示した。
       ```
   - **読点（、）の密度ルール（日本語散文の自然な読点頻度）**:
     - **基本原則: 読点は文のリズムと意味の区切りに必要な箇所だけに打つ。** 1〜2語ごとに機械的に打たない。目安は40〜60字に1読点（1文あたり0〜2個が自然）
     - **読点を打つ箇所**:
       - 主語（〜は/〜が）の後で、文が長くなる場合（主語から述語まで15字以上離れる場合）
       - 接続助詞（〜て/〜ながら/〜けれど等）の後で、意味の区切りが必要な場合
       - 並列要素の区切り（「コーヒーの匂いと、パンの香り」）
       - 誤読防止（修飾関係が曖昧になる場合）
       - 言い淀み・吃音の表現（「は、はい」「お、おはよう」「う、うまっ」等）— これらの読点は必ず保持すること
     - **読点を打たない箇所**:
       - 助詞（の・を・に・で・と・へ・から・まで）の直後 — ❌「カウンターの、内側で、カップを、磨いていた」→ ⭕「カウンターの内側でカップを磨いていた」
       - 短い修飾語と被修飾語の間 — ❌「黒い、万年筆」→ ⭕「黒い万年筆」
       - 述語の直前の短い要素 — ❌「磨いて、いた」→ ⭕「磨いていた」
       - 1文が20字未満の短文内
     - **1文中の読点は原則2個以下。** 3個以上必要な場合は文を分割することを検討する
     - **良い例**: 「柊一はカウンターの内側で、カップを磨いていた。磨きながら視線の端で店内の客席を一度なぞった。」
     - **悪い例**: 「柊一は、カウンターの、内側で、カップを、磨いていた。磨きながら、視線の端で、店内の、客席を、一度、なぞった。」

     - **悪い例（1行ごとに空行 — 禁止）**:
       ```
       　男はカップを置いて、顔だけこちらに向けた。

       「面接か」

       「あ、はい。真白千影です」

       　——声が上ずった。

       　慌てて、低く戻す。
       ```

4. **分量の目安**
   - 1章あたり3000〜5000字（Python `len()` 基準。`wc -m` はUTF-8環境でバイト数を返すため使用禁止）
   - プロットのボリュームに応じて調整
   - プロットに記載された各シーンに対して、情景描写・心理描写・会話のやり取りを十分に展開すること
   - 1つのシーンを1〜2行の要約で済ませず、読者がその場にいるように感じられる密度で描写すること
   - 会話は掛け合いのリズムを大切にし、地の文と交互に配置すること

5. **章間の連続性**
   - 直前の章が既に生成されている場合は、その内容を読み込んで矛盾を防止すること
   - 特に以下の点に注意：
     - キャラクターの位置・状態・服装・持ち物
     - 時間経過や天候
     - 既に起きた出来事や会話の内容
     - 登場人物の感情や関係性の変化
     - **前の章で整理・解決済みの情報に対して、再度驚いたり初耳のように反応させないこと**

6. **視点規律（POV）の厳守**
   - プロットで指定された視点人物を章の最初に確認し、その人物の視点を章全体で貫くこと
   - **視点人物以外の内心描写は絶対に禁止**:
     - ❌ 柊一視点の章で `（マスターの目が怖い）` ← 千影の内心
     - ⭕ 柊一視点の章で `千影が一瞬たじろいだように見えた` ← 柊一から見た千影の外面
   - 括弧付きの内心モノローグ（）は**視点人物のみ**に使用すること
   - 視点人物が見えない・聞こえない・知り得ない情報は描写しないこと
   - 視点切り替えが必要な場合は、空行を挟んで明示的に切り替えること。同一段落内で視点が移動してはならない
   - **よくある視点違反パターン**（全て禁止）:
     - Aの視点章でBの内心を括弧書きで記述する
     - Aの視点章で「Bは〜と思った」「Bは〜を感じた」等、Bの内面を断定する
     - Aの視点章でAがいない場所の出来事を描写する
     - 天丼シーン等で笑いのために別キャラの内心を挿入する → 代わりに外面の描写（表情・仕草・台詞）で表現すること

7. **Show, Don't Tell（描写の質）**
   - **感情の直接説明の禁止**:
     - ❌「悲しかった」「嬉しかった」「不安になった」「怒っていた」「混乱している」
     - ⭕ 身体反応・行動・仕草で表現する（「胸が締め付けられた」「足取りが軽くなった」「拳が震えた」「視線が定まらなかった」）
     - 特に重要なシーン（告白・対決・真実の発覚等）ほど、直接説明を避けて行動と描写で見せること
   - **テーマの直接解説の禁止**:
     - ❌「一番たちの悪い嘘だ」「それは優しい嘘だった」← 作者の声
     - ⭕ キャラクターの行動・選択・葛藤を通じて、読者自身にテーマを感じ取らせること
   - **構造の読者への説明禁止**:
     - ❌「全く違う意味の『おやすみ』を交わしている」← 対比構造の説明
     - ⭕ 二つの「おやすみ」を描写するだけで止め、解釈は読者に委ねること
   - **許容される直接表現**: 視点人物の内心モノローグとして「（嬉しい）」「（怖い）」等の短い感情語を使うのは、コメディやテンポ重視のシーンでは許容する。ただし地の文での長い感情説明は不可

8. **内心モノローグの自然さ**
   - **説明口調の禁止**: キャラクターの内心が読者への状況説明になっていないこと。内心は「思考」であり、解説ナレーションではない
     - ❌ 不自然：（先生の部屋の合鍵を僕が持っている。先生のベランダはここから手を伸ばせば届く距離にある。合鍵は差し入れ用だ。ベランダの距離は建築上の偶然だ）← 自分に状況を説明している
     - ⭕ 自然：（……合鍵、持ってる。ベランダ、すぐ隣。——何を考えてるんだ僕は）← 断片的、省略が多い
   - **他キャラの背景を解説しない**: 他キャラの経歴や事情を内心で読者向けに説明しないこと。言及する場合は間接的に
     - ❌（マスターはあの人、親友に逃げられてるからな——説得力が——）← 経歴の解説
     - ⭕（あの人が言うから重いんだよ——）← 間接的な言及
   - **テンポ重視シーンでの内心の制御**: コメディの掛け合い・クライマックスの連続リアクション等、テンポが命のシーンでは、キャラクターの内心を挟みすぎないこと。挟む場合は短く（1文以内）
   - **判定基準**: 内心モノローグを声に出して読んだとき、独り言として自然に聞こえるか。解説ナレーションに聞こえたら書き直すこと
   - **キャラ名ラベルの禁止（最重要）**: 「キャラ名の内心：（...）」というト書き・脚本形式は小説本文では絶対に使わないこと。プロット側で `柊一の内心：（...）` のような帰属記法が使われていても、本文執筆時には括弧のみ `（...）` に変換すること。内心の帰属は**前後の地の文の文脈**（直前の動作・直前の台詞の話者）で示す
     - ❌ 禁止：`　千影の内心：（硬い）`
     - ⭕ 正しい：`（硬い）`（直前の千影の動作/台詞から千影の内心だと文脈で分かる）
     - **POV切替時**: 同じシーン内で視点が別キャラに移る瞬間は、身体動作の一行を必ず挟んでPOVを示すこと
       - ⭕ `　カップを磨いていた柊一の手が、止まった。` ← この一行で柊一POVに切り替わる
       - ⭕ `（……何だ、今の）` ← 続く内心は柊一のもの、とすぐ分かる

9. **表現の多様性（反復の防止）**
   - **同一フレーズの反復禁止**:
     - 同じ章の締め表現を複数章で使い回さないこと（例：「答えは出ない」を2章以上で使わない）
     - 同じ身体描写（「心臓が跳ねた」「息を呑んだ」等）を同一部内で3回以上使わないこと
     - 意図的な反復（天丼ギャグ、テーマの反復等）は許容するが、意図的でない同一表現は散らすこと
   - **章の締め方のバリエーション**:
     - 内心モノローグで締める、会話で締める、情景描写で締める、動作で締める等、章ごとに締め方を変えること
     - 特に連続する章が全て同じパターン（例：帰り道の内心モノローグ）で終わらないこと
   - **感情表現のバリエーション**:
     - 「心臓が〜」に頼らず、多様な身体描写を使うこと（喉が詰まる、手が震える、呼吸が浅くなる、肩の力が抜ける、指先が冷たくなる、背筋が伸びる等）
     - 「笑った」の連続を避け、「口元が緩む」「頬が緩む」「吹き出す」「破顔する」「目が細くなる」等のバリエーションを使うこと
   - **直前の章の読み込み時に確認すること**: 直前の章で使われた「締め表現」「感情表現の上位3つ」を把握し、今回の章では別の表現を意識的に選ぶこと

9. **読点（、）の打ち方（過剰使用の防止）** — `style-rules.md` C-4 参照
   - **原則**: 地の文の1文に打つ読点は2個までを目安とする。3個以上ある文は必ず見直すこと。読点を増やしすぎると文章が細切れになり、詩的どころか「ためらいがち」「水増し」に見える
   - **特に頻発する過剰パターン（書かないこと）**:
     - 主語直後の余分な読点：❌「彩音は、ブレザーの袖に腕を通した」→ ⭕「彩音はブレザーの袖に腕を通した」（主述が短く続くなら不要）
     - 副詞＋後続語の間の読点：❌「ほんの少しだけ、柔らかい」「じっと、見ていた」「ゆっくりと、消えていく」→ ⭕「ほんの少しだけ柔らかい」「じっと見ていた」「ゆっくりと消えていく」
     - オノマトペと「と」の間の読点：❌「ぱっ、と」「ふっ、と」「びくっ、と」「ぎゅっ、と」→ ⭕「ぱっと」「ふっと」「びくっと」「ぎゅっと」
     - 「の、の」の二重連体：❌「カウンターの中の、男のバイトの姿」→ ⭕「カウンターの中の男のバイトの姿」
     - 同一節内の細切れ分割：❌「千影の視線が、ほんの一瞬だけ、マスターの手元に、留まった」（読点4個）→ ⭕「千影の視線がほんの一瞬だけ、マスターの手元に留まった」（読点1個）
     - 助詞ごとの三連読点：❌「律は、彩音の顔を、じっと、見た」→ ⭕「律は彩音の顔を、じっと見た」
   - **残してよい読点（削ってはいけない）**:
     - ダッシュ「——」前後の劇的な間
     - 逆接・理由節の境界（「〜けれど、〜」「〜から、〜」）
     - 長い主語・修飾節の後の区切り
     - **台詞「」と内心（）の中は作者の地の文ルール対象外**。キャラの声のリズムは壊さないこと
   - **執筆中のセルフチェック**: 段落を書き終えたら、地の文1文ずつに含まれる読点の数を頭の中で数える。3個以上ある文は「本当に全部必要か」を見直し、上記パターンに該当するものを削ること

10. **数字・記号の表記ルール**
   - 小説本文では**漢数字**を使用すること（❌「173cm」→ ⭕「一七三センチ」、❌「3人」→ ⭕「三人」）
   - 例外: 作中の看板・POP・掲示物・メール等の「書かれた文字」を描写する場合は算用数字を許容
   - 三点リーダーは「……」（2つ連続）、ダッシュは「——」（2つ連続）で統一
   - 「！」「？」の後に地の文が続く場合は全角スペースを入れること
   - 章番号の表記は漢数字（❌「第3部完」→ ⭕「第三部完」）

10. **第1章の書き出し戦略**
   - 第1章を執筆する場合、プロットの「★第1話フック設計★」を必ず参照し、冒頭3行で読者を掴むこと
   - **冒頭3行の原則**: 読者は最初の数行で「読み続けるか」を判断する。最初の3行で「何かが起きている」感覚を与えること
   - **効果的な冒頭パターン**:
     - 行動・事件から始める（「銃声が鳴った」「彼女が目を開けると、そこは見知らぬ部屋だった」）
     - 意外な一文で始める（「俺は今日、三度目の死を迎えた」）
     - 強い感情・感覚で始める（「息ができない。心臓が鳴るのが聞こえる」）
     - 謎・疑問を提示して始める（「なぜ、あの子は毎朝屋上にいるのだろう」）
   - **避けるべき冒頭**:
     - 天候や風景の長い描写から始める（「春の陽気が……」）
     - 設定説明から始める（「この世界には魔法が存在する」）
     - 主人公の自己紹介から始める（「俺の名前は○○。普通の高校生だ」）
     - 抽象的な独白から始める（「人は誰しも嘘をつく」）
   - 第1章内で「この物語は何の話なのか」が読者に伝わるようにすること（プロットの「核心の提示」参照）

11. **各章末の引きの実現**
   - プロットの「引き:」フィールドを確認し、章末に引きを実現すること
   - **引きの種類別の書き方**:
     - **疑問型**: 章の最後に未解決の問いを残す。直接的な疑問文でなくてもよいが、読者に「なぜ？」「どういうこと？」と思わせること
     - **危機型**: 差し迫った危険・ピンチの瞬間で切る。解決を次章に持ち越すこと
     - **転換型**: 状況を一変させる情報・出来事で章を閉じる。最後の1〜2行で転換を入れること
     - **感情型**: キャラクターの強い感情（決意、絶望、歓喜、悲嘆）の頂点で切る。余韻を残すこと
     - **期待型**: 次に起きることへの期待や予感を煽って終わる。「明日」「次の瞬間」等への橋渡し
   - **避けるべき章末**:
     - 日常の延長でそのまま終わる（「そして眠りについた」「今日も平和だった」）
     - 全てが解決してすっきり終わる（次を読む動機がなくなる）
     - 引きなく余韻だけで終わる（最終章・エピローグを除く）
   - 章末の最後の1〜3行に引きの核となる要素を配置すること

12. **場面の緩急（プロース・ダイナミクス）** — `style-rules.md` E節 / `forbidden-patterns.md` #21〜#23 参照
    - **根本原則**: 「全てのシーンを同じ丁寧さ・同じ温度で書く」のはAI生成文の最大の弱点。場面の感情強度に応じて文章のスタイル自体を切り替えること
    - **クライマックス（告白・正体バレ・対決等）**:
      - 文を短くする（1文平均15字以下）
      - 過去形から**現在形**に切り替えて臨場感を出す（`style-rules.md` E-3）
      - 内心モノローグ（ ）を**使わない**。行動と身体反応のみで描写する
      - 体言止めを連続させてリズムを加速する
      - 読点を減らし、句点で畳み掛ける
    - **コメディ場面（掛け合い・ツッコミ・勘違い暴露等）**:
      - 地の文を**最小限**にし、台詞の応酬でテンポを作る
      - ツッコミの直前に地の文を挟まない（`dialogue-guidelines.md` セクション6）
      - 「「「「」」」」等の同時台詞、間の取り方、リアクションの順番でリズムを作る
      - 内心ツッコミ（ ）は短い1発で。解説型の長い内省は入れない
    - **静かな場面（余韻・日常・関係性の確認等）**:
      - 一文を長めに取り、読点で余韻を作る
      - 五感描写（音・匂い・温度・光）を厚くする
      - 会話は少なく、沈黙と仕草で関係性を見せる
    - **日常場面**:
      - 内心モノローグに頼らず、会話と動作で関係性の変化を見せる
      - 背景描写で時間の経過や季節を伝える
    - **判定基準**: 1つの章の中で「この場面は他の場面と文章のリズムが違う」と感じられるか。全場面が同じリズムで進行する場合は緩急不足

13. **文末表現のバリエーション** — `style-rules.md` E節 参照
    - 「〜た」「〜ていた」「〜だった」の連続は3文まで。4文目は必ず別の文末（現在形・体言止め・疑問形・省略文・倒置法）を入れること
    - 特に「〜ていた」（継続過去）は1段落に2回までが上限。多用すると全てが「遠景から眺めている」距離感になる
    - クライマックスでは意識的に現在形に切り替え、読者を「今この瞬間」に引き込むこと

14. **内心モノローグの頻度制御** — `style-rules.md` F節 参照
    - 1章あたりの（ ）は**15個以下**。15個を超えたら「この（ ）がないと読者が理解できないか」を基準に削る
    - （ ）が3行連続したら、必ず次の行は身体動作・地の文にする。4行以上の連続（ ）は禁止
    - 「（……変なの）」「（……わからない）」系の保留型は原則削除。行動描写に置き換える
    - クライマックスでは（ ）を使わず、行動と身体反応のみで感情を伝える

15. **演出手法の使用回数制御** — `style-rules.md` G節 / `forbidden-patterns.md` #21〜#23 参照
    - 「手が止まった」系は1部2回まで、全編5回まで
    - 「心臓が跳ねた」「耳が赤くなった」等の身体反応はキャラ固有のものを使い分ける（`character.md`の「感情表現パターン」参照）
    - 背景動作の反復（カップ磨き等）は1部3回まで
    - 場面転換のダッシュ「——」は1章2回まで。3回目以降は空行・音・対比・人物移動等の別手法を使う
    - 「〇〇は気づいていない/知らない」系の締めは**使用禁止**。行動描写のみで示す

16. **シーンの変化義務（各シーンで何かが変わる）**
    - 各シーンの終了時に、開始時と比べて**最低1つの変��**がなければならない。変化の種類は以下のいずれか:
      - **感情の変化**: キャラの感情状態が動いた（好意↑、警戒↓、不安→覚悟 等）
      - **関係性の変化**: 二人の距離・呼び方・態度が変わっ���
      - **情報の変化**: キャラまたは読者が新しい事実を知った
      - **状況の変化**: 物理的な状態・立場・環境が変わった
      - **決断**: キャラが何かを選んだ・決めた
    - 「何も変わらな���日常風景」は禁止。日常シーンでも、微小な変化（視線が合う時間が1秒長くなった等）を必ず含め��
    - **検証方法**: シーンを書き終えたら「このシーンで何が変わったか」を一文で言えるか自問する。言えなければ、変化の種を加筆する

17. **会話のサブテキスト** — `dialogue-guidelines.md` セクション9 参照
    - 感情が強い場面ほど、キャラは本音を直接言わない。話題を逸らす・質問で返す・非回答・過剰な親切等のサブテキ���ト技法を使う
    - 「好き」「嫌い」「怖い」「嬉しい」等の感情名詞を台詞で直接言わせるのは**物語の最終盤の決定的場面のみ**。途中経過では行動・身体反応・間接表現で匂わせる（`forbidden-patterns.md` #24）

18. **五感バランス** — `style-rules.md` H節 参照
    - 1シーンに視覚以外の感覚（聴覚・嗅覚・��覚・味覚・温度感覚）を��低1つ含める
    - 場所の描写では `worldbuilding.md` の「五感プロファイル」を参照し、その場所固有の感覚情報を使う

19. **情報密度のリズム（出来事と解説の配置）** — `style-rules.md` A-7 / `forbidden-patterns.md` #25 参照
    - 出来事（身体動作・触感・物音・視覚的事象）と解説（内心括弧書き・地の文の解釈）を等間隔で交互配置しない
    - 出来事の直後に解説を置く場合、解説は出来事より短くする。事象1：解説1までを目安とし、解説が出来事の3倍を超えたら削る
    - **身体接触・五感的事象の直後は短い余韻で止め、長い解釈モノローグを連続配置しない**。最後の一文で止めるべき箇所をその前に全部解説してしまわないこと
    - 触感（手・指・吐息・体温・温度差）を描いた直後、視点キャラ複数名分の括弧書き独白を交互に並べることは禁止。片側の独白は1〜2行に圧縮するか、削除する
    - **チェック**: 段落内の「出来事系」と「解説系」の文比率を測る。1:3 を超える段落は要削減

20. **反射的間投詞の抑制** — `style-rules.md` A-8 参照
    - 「（あ）」「（やばい）」「（待って）」「（え）」「（えっ）」「（——え）」「（あっ）」のような単独括弧書き間投詞は**1章合計3回まで**（`rules.md` の「反射的間投詞の上限」があればそちらを優先）
    - 人間が本当に動揺したとき、こういう言葉はむしろ思考から消える。動揺は動作と身体で描く
    - 「（あ）」→「指がカップの上で止まった」のように、動作描写・身体反応に置換する。前後文脈で意味が通る場合は削除でもよい
    - 例外：コメディシーンのツッコミ的な「（あ）」「（えっ）」は許容範囲を広げる。シリアスシーンでは厳守

21. **テーマワードの自己貼り直し禁止** — `forbidden-patterns.md` #26 / `rules.md`「テーマワード管理」セクション参照
    - 作品のテーマを構成するキーワード（例：「嘘」「正直」「演技」「役作り」等）を、当該キャラ本人が自分の状態に対して内心で繰り返し貼り直さないこと
    - テーマは登場人物が **気づいていない場所** で動いているとき、いちばん強く効く。本人にラベリングさせると読者の中でキーワードが摩耗する
    - テーマワードは「外部からの観察」「他キャラのセリフ・独白」「地の文の象徴配置」として現れるとき最大効率になる
    - **チェック**: `rules.md` に「テーマワード管理」セクションがあれば、そのB区分（自己ラベリング・削減候補）に該当する独白を1章あたり上限以内に抑える

#### 文体別の執筆指示

| 文体 | 指示内容 |
|------|----------|
| 標準 | 読みやすく親しみやすい現代的な文体で執筆。会話文は自然で、地の文は簡潔かつ分かりやすく |
| 文学的 | 格調高く重厚な文体で執筆。比喩や情景描写を丁寧に織り込み、深い心理描写を重視 |
| ライト | 軽快でテンポの良い文体で執筆。短い文章を中心に、リズム感とスピード感を重視 |
| コメディ | ボケとツッコミのテンポを最重視した文体で執筆。会話の掛け合いは漫才的なリズムで、地の文でも登場人物の内心ツッコミ（括弧書きの心の声）を多用する。勘違い・すれ違い・空回りを読者にわかる形で描写し、「読者だけが真実を知っている」構造で笑いを生む。シリアスなシーンでも完全にシリアスにせず、どこかにクスッと笑える要素を残す。感情的なシーンは笑いから自然に切なさ・温かさへ転調させ、緩急をつける |
| ドラマチック | ドラマチックで感情表現豊かな文体で執筆。緊迫感・高揚感を演出し、印象的な表現を使用 |
| 硬派 | 硬質で冷静な文体で執筆。論理的・客観的な描写を心がけ、感情表現は抑制的に |
| 詩的 | 叙情的で美しい文体で執筆。詩的な表現や繊細な感情描写、美しい比喩を織り交ぜる |
| フェチズム特化 | 谷崎潤一郎・川端康成系の文体で執筆。体の細部（足袋、襟元、首筋、指、髪の生え際、耳たぶ、足の甲、踝、項等）・所作の機微・布越しの感触・陰翳に偏執的な視線を注ぐ。直接的な性愛描写・性器・性的行為の単語は使わず、視線・距離・温度・影・布の擦れ・残り香で間接的に官能を立ち上げる。谷崎的な息の長い文（句読点を抑え、修飾節を畳みかけて一文に納める）と川端的な短い断片の余韻（体言止め・省略・空白）を場面で使い分ける。視点キャラは対象を「眺める側／奉仕する側」に置き、近づけない距離感・触れられない緊張・見るだけの執心を保つ。テーマワード（「美しい」「好き」「綺麗」等）の地の文での直接ラベリングは禁止——対象の細部描写で読者に推測させる。明るい場所より薄明・陰翳・夕暮れ・障子越しの光を選び、はっきりした輪郭より曖昧な影を描く |

#### 特殊セクションの執筆指示

- **第1章**（`chapter01.txt`）: プロットの「★第1話フック設計★」に従い、冒頭3行でフックを実現すること。核心の提示と問いの設定も第1章内で達成すること。第1章は読者が作品を読み続けるかを決める最重要章であり、他の章以上に掴みを意識すること
- **結末**（`## 結末`）: 物語の締めくくりとして、伏線の回収・感情の解放・余韻の残る文章を意識

### ステップ4.5: 品質検証と自動修正（全モード共通・必須）

**章を1つ生成するたびに、保存の前に必ず以下の検証ルーチンを実行すること。**
このルーチンはモード（A/B/C/D）や確認方法（逐次/一括）に関わらず、全ての章生成で必ず実行する。

- 身体接触・触感シーンを書く章 → ベンチマーク1（余韻で止める）

1. プロジェクト固有のルール（`projects/{作品名}/style_notes.md` や `check_notes.md` があれば）
2. 作品のジャンル別文体（コメディ章では台詞80字制限を緩和する等）
3. `_shared/references/` の汎用ルール

**作品固有ファイルが存在しない場合**は、汎用ルールをそのまま適用する。

#### A. 文字数検証

1. **文字数計測**: 生成した章の本文をPython `len()` で計測する
   ```python
   python -c "print(len(open('生成したファイルパス', encoding='utf-8').read()))"
   ```

2. **判定**: 計測結果を目安の下限値（3000字）と比較する
   - **3000字以上** → 合格。品質検証に進む
   - **3000字未満** → 不足。自動加筆に進む

3. **自動加筆**（3000字未満の場合）:
   - 現在の本文を読み込む
   - 対応するプロットの内容を再確認する
   - 以下の観点で加筆・膨らませを行い、ファイルを上書き保存する：
     - プロットに記載されたシーンで描写が薄い箇所に情景描写・心理描写を追加
     - 会話の掛け合いを増やす（地の文と交互に配置）
     - 五感描写（視覚・聴覚・嗅覚・触覚・味覚）を補強
     - キャラクターの動作・表情・仕草の描写を追加
     - 場面転換の間に繋ぎの描写を追加
   - **注意**: 加筆はあくまで既存の内容を膨らませること。プロットにない新しい展開やイベントを追加してはならない

4. **再計測**: 加筆後に再度 `len()` で計測し、3000字以上になったことを確認する
   - まだ不足の場合はステップ3を再度実行する（最大2回まで）
   - 2回加筆しても不足の場合は、現状のまま進行し、完了報告で不足章として明示する

#### B. 品質検証（自動チェック）

文字数検証の通過後、生成した本文を以下の観点で自動チェックすること。問題があれば**即座に修正してから保存**する。

**チェック1: メタ記述の混入**
生成した本文中に以下が含まれていないか確認する：
- 話数番号（「第○話」「第○章」— ただし章タイトル行は除く）
- 「読者」という語（章タイトルや台詞内の正当な使用を除く）
- プロットのセクション名（「読者への効果」「伏線」「シーン1」等）
- 設定メモの語句（「character設定」「worldbuilding」「プロット」等）

**チェック2: 視点違反（プロット指定視点との照合を含む・最重要）**

このチェックは単なる「内心描写の確認」ではなく、**ステップ3.7で宣言した視点人物との照合**を必ず行う：

1. **プロット指定視点との照合（最重要）**:
   - ステップ3.7の執筆契約で宣言した「視点人物」を改めて確認する
   - 生成した本文の章冒頭〜章末まで、視点が契約通りになっているか確認する
   - プロットが「彩音（メイン）→律」と指定していたのに、本文が全編律視点になっていたら**即座に章を破棄して再生成**
   - プロットに「視点」指定がある以上、執筆者の判断で変更することは許されない

2. **視点人物以外の内心描写**:
   - 視点人物以外のキャラクターの内心を括弧（）で記述していないか
   - 「○○は〜と思った」「○○は〜を感じた」等、視点人物以外の内面を断定していないか

3. **視点切替の明示**:
   - プロットが複数の視点（例: 彩音→律）を指定している場合、本文内で視点切替が発生している箇所に空行が挟まれているか
   - 同一段落内で視点が移動していないか

**チェック2B: プロット忠実性（ステップ3.7の契約との照合・最重要）**

ステップ3.7で宣言した執筆契約と生成した本文を逐項目で照合する。1つでも違反があれば**即座に章を破棄して再生成**すること：

1. **シーン構成の完全性**:
   - ステップ3.7で宣言した「シーン構成: シーン1→シーン2→…」の全シーンが本文に含まれているか
   - シーンの順序が入れ替わっていないか
   - シーンが削除されていないか
   - プロットに存在しないシーンが追加されていないか

2. **登場キャラの完全一致**:
   - ステップ3.7で宣言した「登場キャラ」と本文の登場キャラが完全に一致しているか
   - プロットに登場しないキャラが本文に登場していないか（最重要）
   - プロットに登場するキャラが本文から欠落していないか

3. **キャラ同一性（姓名取り違え防止・最重要）**:
   - 本文に登場する人物名を全て抽出する
   - 抽出した人物名を `character.md` の登場キャラ名と照合する
   - `character.md` に存在しない名前が地の文・台詞に登場していたら即座に修正
   - 同一キャラの複数呼称（姓・名・フルネーム・愛称）が別キャラとして描写されていないか確認する
     - 例: `character.md` に「真白 千影（ましろ ちかげ）」と定義されている場合、本文中で「千影」と「真白」を別人として扱うことは絶対禁止
     - 章内で「千影」と呼ぶシーンと「真白」と呼ぶシーンが混在しても構わないが、それらは**同一人物として**描写されなければならない
   - ステップ3.7の契約宣言で「呼称統一」を明記した場合、その統一ルールが本文で守られているか確認する

4. **プロットのキーセリフの反映**:
   - プロット該当節で「」で囲まれた台詞のうち、シーンの核となるセリフが本文に反映されているか
   - プロット通りの言葉で使う必要はないが、意味・ニュアンスが保たれているか
   - プロットの決め台詞（「俺は嘘つきが嫌いだ」等）は原文通りに使うこと

5. **引きの型の一致**:
   - ステップ3.7で宣言した「引きの型」と本文の章末の引きが一致しているか
   - プロットが「感情型」と指定しているのに章末が「日常の延長」になっていないか

**このチェック2Bで1つでも違反が見つかった場合、品質修正ではなく章の完全再生成を選ぶこと。** 部分修正では本質的な逸脱は直らないため、該当章のプロット節を再度読み直してゼロから書き直す。

**チェック3: 重複行**
- 同一文または同一段落が連続して2回出現していないか（コピペミスの検出）

**チェック4: 算用数字の混入**
- 本文中に算用数字（0-9）が使われていないか確認する（看板・POP等の描写内を除く）

**チェック5: 表現の反復**（直前の章がある場合）
- 直前の章と同じ締め表現を使っていないか
- 同一の感情表現（「心臓が跳ねた」等）を3回以上使っていないか

**チェック6: 章末の引き**（最終章・エピローグを除く）
- プロットの「引き:」フィールドで指定された引きの種類が実現されているか
- 章の最後の1〜3行に引きの核となる要素が配置されているか
- 日常の延長でそのまま終わっていないか、全てが解決してすっきり終わっていないか
- 引きが弱い場合は、章末を書き直すこと

**チェック7: 内心モノローグの説明口調**
- キャラクターの内心が読者への状況説明になっていないか（「先生の部屋の合鍵を僕が持っている。ベランダの距離は建築上の偶然だ」のような自分に状況を説明する内心）
- 他キャラの経歴・事情を内心で解説していないか
- コメディやクライマックスの掛け合いの間に長い内心を挟んでテンポを殺していないか

**チェック8: キャラクター認知の整合性**
- 前の章で既に知った・整理した情報に、再度驚いたり初耳のように反応していないか
- そのキャラクターがまだ知らない情報を前提にした行動・判断・感情を持っていないか
- timeline.md「キャラクター知識・認知の変遷」が存在する場合はそれと照合すること

**チェック9: キャラクター行動・心理・独白の設定整合**
- キャラクターの行動がcharacter.md の性格・価値観・能力から自然に導かれているか。設定と矛盾する行動（臆病な設定で脈絡なく大胆、冷静な設定で根拠なく動揺等）がないか
- 心理描写（感情反応・恐怖の対象・怒りの沸点）がキャラクターの性格・背景・トラウマ設定と一致しているか
- 内心独白の語彙・思考の癖（楽観的/悲観的、論理的/直感的）がキャラクターの知性・教養・性格設定と整合しているか。口調設定と内心の語彙が乖離していないか
- 設定と異なる行動・心理がある場合、プロット上に変化のきっかけが明示されているか確認すること

問題が見つかった場合は、該当箇所を修正してからファイルに保存すること。

**チェック10: 文末表現の単調さ** — `style-rules.md` E節 参照
- 「〜た」「〜ていた」「〜だった」が4文以上連続している箇所がないか確認する
- 特に「〜ていた」が1段落に3回以上出現していないか確認する
- 問題があれば、体言止め・現在形・疑問形・省略文に差し替えて文末を散らすこと

**チェック11: 内心モノローグの頻度と演出反復** — `style-rules.md` F/G節、`forbidden-patterns.md` #21〜#23 参照
- 章全体の（ ）の個数を数え、15個を超えていないか確認する。超過している場合は行動描写に置き換えて削る
- （ ）が4行以上連続している箇所がないか確認する。あれば身体動作の行を挟む
- 「手が止まった」「心臓が跳ねた」「耳が赤くなった」等の汎用演出が多用されていないか確認する
- ダッシュ「——」による場面転換が1章内で3回以上使われていないか確認する
- 章末が「〇〇は気づいていない/知らない」系の全知視点で終わっていないか確認する

**チェック12: 情報密度のリズム** — `style-rules.md` A-7 / `forbidden-patterns.md` #25 参照
- 段落内で「出来事を描く文」と「解釈・内心を描く文」が等間隔で交互配置されていないか確認する
- 身体接触・触感・五感的事象の直後3段落以内に、視点キャラ複数名分の括弧書き独白（2行以上）が連続していないか確認する
- 「最後の一文で止めるべき余韻シーン」を、その前に全部解説してしまっていないか確認する
- 該当があれば、解説側を削るか1〜2行に圧縮する

**チェック13: 反射的間投詞の頻発** — `style-rules.md` A-8 参照
- 「（あ）」「（やばい）」「（待って）」「（え）」「（えっ）」「（——え）」「（あっ）」が単独行で出現する回数を章内でカウントする
- 合計が3回（または `rules.md` の上限値）を超えていれば、超過分を動作描写・身体反応に置換、または削除する
- コメディシーンのツッコミ用途は除外可能。シリアスシーンでは厳守

**チェック14: テーマワードの自己貼り直し**（`rules.md` 設定がある場合のみ）— `forbidden-patterns.md` #26 参照
- `rules.md` の「テーマワード管理」セクションがあれば、その体現キャラの内心独白でB区分（自己ラベリング）に該当する語の出現を章内でカウントする
- 1章あたり上限を超えていれば、超過分を削除するか、外部視点（他キャラの呟き・地の文の象徴配置）に移す

#### C. 報告

章タイトルと最終文字数を1行で報告する（例：`第三章「転校生の微笑み」— 3,420字 ✓`）
- 加筆が発生した場合は `（加筆済み）` を付記する
- 品質修正が発生した場合は `（品質修正済み）` を付記する

#### 結末・エピローグの扱い

結末（`chapter_end.txt`）およびエピローグ（`epilogue.txt`）は通常の章より短くてよい。
これらのファイルについては下限を1000字とする。

### ステップ5: 保存

生成した本文を以下のルールでファイルに保存します。

#### ファイル命名規則

- **部構造がない場合**:
  - 第1章 → `projects/$ARGUMENTS/chapter01.txt`
  - 第2章 → `projects/$ARGUMENTS/chapter02.txt`
  - 結末 → `projects/$ARGUMENTS/chapter_end.txt`
  - エピローグ → `projects/$ARGUMENTS/epilogue.txt`

- **部構造がある場合**:
  - 第一部・第1章 → `projects/$ARGUMENTS/part01/chapter01.txt`
  - 第二部・第4章 → `projects/$ARGUMENTS/part02/chapter04.txt`
  - 結末 → `projects/$ARGUMENTS/chapter_end.txt`（ルート直下）
  - エピローグ → `projects/$ARGUMENTS/epilogue.txt`（ルート直下）

#### 保存の確認

ユーザーが選択した確認方法に従って保存を行います：

- **逐次確認モード**（デフォルト）:
  - 各章を生成するたびにユーザーに内容を提示し、保存してよいか確認を取ること
  - 既にファイルが存在する場合は上書き確認を取ること

- **一括確認モード**（全章一括生成時のみ選択可）:
  - 全章を生成後、章タイトルと文字数の一覧のみ提示
  - ユーザーが一括保存を承認したら全ファイルを保存
  - 保存前の個別内容確認は行わない
  - 既存ファイルがある場合は事前に一覧表示し、上書きの承認を得ること

### ステップ6: 完了報告

全ての生成が完了したら、生成したファイルの一覧と各章の文字数を報告してください。

文字数の計測には以下のPythonスクリプトを使用すること（`wc -m` は使用禁止）：
```python
python -c "
import os
base = 'projects/$ARGUMENTS'
total = 0
for root, dirs, files in os.walk(base):
    for f in sorted(files):
        if f.endswith('.txt'):
            path = os.path.join(root, f)
            with open(path, 'r', encoding='utf-8') as fh:
                n = len(fh.read())
            rel = os.path.relpath(path, base)
            print(f'  {rel}: {n:,}字')
            total += n
print(f'合計: {total:,}字')
"
```

報告例：
```
生成完了：
- chapter01.txt「春風と卵焼き」（6,230字）
- chapter02.txt「妹の門番」（5,890字）
- chapter03.txt「転校生の微笑み」（7,510字）
合計: 19,630字
```
