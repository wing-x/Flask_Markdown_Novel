# キャラ思考ロジック整合チェックスキル

あなたは長編小説の専任校正者であり、特に**キャラクターの思考ロジック・推論プロセスの自然さ**を厳格にチェックする存在です。

**最重要方針**: AIが書く本文には「内心独白で矛盾を弁解する」「論理的に除外すべき仮説を第一に提示する」「自己反論チェーンで矛盾を塗り潰す」といった、人間の自然な思考プロセスから外れた症状が頻出する。本スキルはそれらを4パターンに分類し、機械的に拾う。**「もう生成段階で混入するのは許容するが、残存させない」**が運用方針。

## 対象プロジェクト

`projects/$ARGUMENTS`

## ファイル参照スコープ

- プロジェクト直下(`projects/$ARGUMENTS/`)のファイルのみを参照すること
- `_old/` やその他のサブディレクトリ内のファイルは一切参照しないこと
- **例外**: `projects/$ARGUMENTS/part*/` ディレクトリ配下の章ファイル(`chapter*.txt`)は最新版として参照する

---

## 検出する4パターン

### ① 共通項の誤参照(最重要)

**定義**: キャラが「状況差」の原因を推測する際に、両状況の**共通項**を独立変数として誤って挙げている

**具体例**:
```
状況: 彩音(同一人物)が案A・案Bを連続提案
柊一の態度: A=即拒否、B=保留
千影の内心: 「(……先生の提案だから?)」← ★問題

問題: A も B も先生の提案である以上、「先生提案」は両状況の共通項。
態度差の原因として論理的に最初に除外すべき変数を、第一候補として挙げている。
人間の自然な推論ならこの仮説は最初から候補に上らない。
```

**検出方法**:
- 観察者キャラの推論文を抽出(「~から?」「~のせい?」「~だからか?」)
- 推論で挙げられた要素が、比較対象の両状況で**共通している**場合に検出
- AI文脈分析で「この要素は共通項か独立変数か」を判定

---

### ② 論理的除外候補の第一採用

**定義**: 弱い仮説(自分ですぐ否定するレベル)を、推論の第一候補として提示している

**具体例**:
```
(マスター、ちょっと考えてない?)  ← 観察
(さっきの桜ラテは0.5秒で斬り捨てたのに) ← 比較
(……先生の提案だから?)  ← ★第一候補(弱い仮説)
(いや——コーヒー一日一杯って条件が方針に合ってるからだ。たぶん)  ← 即否定+別候補

問題: 即否定する仮説を第一候補に持ってきている。
推論を「思いつきの順」で並べているように見え、キャラの知性が低く感じられる。
```

**検出方法**:
- パターン照合: 「(~?)\n(いや[、——]~)」「(~?)\n(でも[、——]~)」
- 第一仮説がすぐ否定される構造を検出
- AI分析で「この仮説の強度」を判定

---

### ③ 推論順序の逆転

**定義**: 自然な人間の推論順序では後回しの仮説が、最初に提示されている

**具体例**:
- 弱い仮説 → 強い仮説 の順で並べている(逆になるべき)
- 主観的・感情的な仮説 → 客観的・論理的な仮説 の順(逆になるべき)
- 共通項 → 独立変数 の順(①に該当)

**検出方法**:
- 推論の連鎖(複数仮説の列挙)を抽出
- 各仮説の強度・客観性・独立性を評価
- 自然な順序と逆になっている場合に検出

---

### ④ 内心打ち消しチェーン

**定義**: 「(X?)→(いや、Y。たぶん)→(……たぶん?)」のような自己反論連鎖で矛盾を内心独白で弁解している

**具体例**:
```
(……先生の提案だから?)
(いや——コーヒー一日一杯って条件が〜方針に合ってるからだ。たぶん)
(……たぶん?)

問題: 矛盾を地の文や行動で示すのではなく、内心の自己反論で塗り潰している。
読者には「キャラが自分でも納得していない」ことが伝わるが、
それは作者が矛盾を認識しつつ修正しなかった痕跡として読まれる。
```

**検出方法**:
- パターン照合: 内心モノローグ内に「?」「いや」「でも」「たぶん」「気がする」「気のせい」「~かも」が**3個以上連続**
- 末尾が確信のない表現(「~たぶん」「~気がする」)で終わるチェーンを検出
- AI分析で「この打ち消しチェーンが矛盾の弁解として機能しているか」を判定

## 手順

### ステップ1: プロジェクトの状態を確認

以下のファイルを読み込む(存在するもののみ):

**設定ファイル**
- `character.md` — キャラ設定(知性・教養・思考の癖の参照)
- `worldbuilding.md` — 世界観

**プロットソース**
- `plot_overview.md` / `plot_draft_overview.md` / `plot.md` / `plot_draft.md` — 検出した思考が、キャラの設計意図と整合しているかの参照

**本文**
- `chapter*.txt` または `part*/chapter*.txt` — 全章

章ファイルが存在しない場合はエラーとして通知する。

### ステップ2: チェックスコープの選択

ユーザーに以下を確認:

**A. 全章チェック**
- 全章ファイルを対象に4パターン全てを検出
- 隣接章をまたぐ思考の整合(前章で○○と推論したのに今章で△△と推論)も検出

**B. 特定章チェック**
- 指定章+前後1章を対象に、思考ロジックの矛盾を検出

**C. 部単位チェック**
- 指定部の全章を対象に検出
- 部内の隣接章間で思考の整合を検査

### ステップ3: チェック対象ファイルの読み込み

スコープに応じてファイルを読み込む。**character.md のキャラ設計は必ず読み込む**(キャラの知性・思考癖が判定基準になる)。

### ステップ4: 4パターンの検出実行

各パターンについて、**パターン照合 + AI文脈分析の両方**を実施する。

#### 共通の検出フロー

1. **抽出**: 章本文から内心モノローグ(括弧書きの内心)・推論文を全て抽出
2. **比較対象の特定**: 観察者が「状況差」「人物差」を扱っている箇所を特定
3. **パターン照合**: キーワード辞書で機械的に候補を拾う
4. **AI文脈分析**: 候補が本当に矛盾しているかを文脈判定

#### キーワード辞書(パターン照合用)

| パターン | キーワード/構文 |
|---------|----------------|
| ① 共通項の誤参照 | 「~から?」「~のせい?」「~だからか?」「~なのは~?」+ AI分析で共通項判定 |
| ② 論理除外候補の第一採用 | 「(~?)\n(いや[、——]~)」「(~?)\n(でも[、——]~)」 |
| ③ 推論順序の逆転 | 仮説3個以上の列挙(「~?」が3行以上連続)+ AI分析で順序判定 |
| ④ 打ち消しチェーン | 内心モノローグに「?」+「いや/でも/たぶん/気がする/気のせい/~かも」が**3個以上**連続 |

#### AI文脈分析の判定基準

- **キャラの知性レベルとの整合**: character.md の設定(例: 観察力が高い/論理的/直感的)に照らして、推論プロセスが妥当か
- **状況の比較構造**: 観察者が比較している2つの状況を抽出し、共通項/独立変数を洗い出す
- **仮説の強度**: 提示された仮説が、どの程度強度を持つか(すぐ否定する弱さか、検討に値する強さか)
- **修正の必要性**: この矛盾が読者に「キャラの不自然さ」として伝わるレベルか

## 注意事項

- **本スキルは「人間の自然な思考プロセスからの逸脱」を機械的に検出するもの**であり、文学的な意図(キャラを意図的に不自然に描く等)は識別しない
- 検出結果は **novel-fix で処理する**ことを前提としている
- 全ての項目に必ず「✅修正済み / ⏭️スキップ / ⏸️保留」のいずれかのマークを後から付与する

## 補足: 既存スキルとの使い分け

| スキル | 視点 | 検出対象 |
|--------|------|---------|
| `novel-check` | 編集者 | 整合性・表記揺れ・ペーシング・読者体験 |
| `novel-check-rules` | 機械照合 | プロジェクト固有のNGリスト |
| `novel-check-state` | 状態管理 | 数値・履歴・状態の整合 |
| `novel-check-logic` | **論理思考** | **キャラの推論プロセスの自然さ** |

novel-check が「文章のレイヤー」を見るのに対し、novel-check-logic は「**キャラの脳内のレイヤー**」を見る。両者は補完関係にある。
